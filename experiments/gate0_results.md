## 0. 一句话结论

**在 MSR-VTT 上,这个模型的检索是"时间盲"的:把 8 帧完全打乱,分数一点不掉
(t2v 42.50 → 42.6);但把 8 帧换成同一帧重复,分数崩掉 13 个点(42.50 → 29.5)。**
⇒ **帧的"多样性"值 ~13 个 R@1,帧的"顺序"值 ~0。** MSR-VTT 因此**不能**用来判定任何
时序类改动的优劣 —— 这一点现在是在我们自己的模型上测出来的,不是引用别人的论文。

## 2. 为什么这个"零效应"是可信的 —— `freeze` 是阳性对照

这是本轮方法学上最重要的一点。**一个"零效应"最常见的死法是开关根本没生效。**
本轮不存在这个问题:同一个 `MVC_FRAME_PERTURB` 钩子,在 `freeze` 上打出了
**−13 个点、两口径同向**的巨大效应。⇒ 钩子确实在改帧、评测确实对帧内容敏感,
**因此 `shuffle` 的 0 是一个真的零,不是坏掉的开关。**

(代码侧另有保证:不设 `MVC_FRAME_PERTURB` 时 `maybe_perturb_frames` **返回同一个对象**,
本地已单测;`shuffle` 按样本 index 确定性设种,可复现。)

## 3. 这验证了什么 / 没验证什么

**验证了(round-2 §0 F1 的预测,在我们自己的模型上成立):**
均值池化头**无条件时间盲** —— 集合的均值对任意重排不变。全模型的顺序敏感性只能来自
backbone,而实测下来这部分**在 MSR-VTT 的检索指标上贡献 ≈ 0**。

**顺带验证了 C2 的前提(好消息):** 帧数是有价值的 —— 8 张不同的帧比 1 张重复的帧值
**13 个 R@1**。所以"帧预算作为部署旋钮"这条线的动机是成立的;不成立的只是"帧的**顺序**"。

**没验证 / 必须诚实说明的三条:**

1. **`freeze` ≠ "单帧模型不行"。** 这是拿一个用 8 张多样帧训练的模型、在测试期只喂 1 帧,
   属于**分布偏移**。它给的是"饿掉多帧信息的代价"的**上界**,不等于 ATP / 单帧偏置文献里
   "为单帧规制训练 + 帧集成"的干净对照。别把这 13 个点写成"我们反驳了单帧偏置"。
2. **只测了 MSR-VTT 这一半。** SSv2-MC 全部四个扰动都**没跑起来**(见 §4)。所以目前只能说
   "MSR-VTT 测不出顺序",**还不能**区分"模型确实没有顺序信息" vs "模型有、但 MSR-VTT 不奖励"。
   round-2 §2c 的判读表需要两边都有数才能落到某一行。
3. **`reverse` 的 −1 不要当成效应。** 两口径不同向(−1.2 vs −0.1),且落在 ±1.6 的二项噪声带内。
   若真想追这 1 个点,需要换种子重跑 + 多基准符号检验(round-2 §1.1)。

## 7. 静态审计(任务 A)—— 2026-07-24 首次在真权重上运行

### 7.1 `temporal_embedding`:**不是零**(与"它可能从未被使用"的假设相反)

| stage-4 block | ‖E‖ | 位置间相对离散度 |
|---|---|---|
| `network.7.0` | 0.107345 | 0.2162 |
| `network.7.1` | 0.101091 | 0.1703 |
| `network.7.2` | 0.115356 | 0.1483 |
| `network.7.3` | 0.149651 | 0.1446 |

四块**全部**离开了零初始化,且逐位置范数彼此不同
(如 7.0 的 `[0.0402, 0.0278, 0.0231, 0.0439, 0.0369, 0.0423, 0.0464, 0.0369]`)
⇒ **stage-4 在参数层面确实区分了帧位置**,这条通路没死。

**但这不等于顺序敏感性。** 按 round-2 **F2**,`temporal_embedding` 是**加性**的
(`x = x + resize_temporal_embedding(...)`),而加性位置编码会被均值池化**精确抹掉** ——
它只能经由下游非线性(stage-4 attention → convffn → conv_exp → head)间接影响池化后的嵌入,
这是一条**间接且弱**的通路。与行为侧 GATE-0(打乱 8 帧不掉分)放在一起看,结论是:
**参数上有弱的位置信息,但没有转化成行为上的顺序敏感性。**

⚠️ 逐位置范数看不出干净的"方向"结构(不是单调斜坡,更像两端效应+噪声),但 8 个数不足以下判断。
脚本已加**时间反转反对称占比**(E 沿 T 翻转与自身比;≈0 ⇒ 沿时间回文 ⇒ **原则上编码不了方向**),
下次跑会直接给出这个数。

### 7.2 时间卷积核:首次运行未测到 —— 官方权重是**训练态**

`mobileviclip_small.pt` 里没有 `reparam_conv_1d`(那是推理态的键),只有未融合的分支:
`mixer_1d.rbr_conv.0.conv.weight` (C,1,3)、`mixer_1d.rbr_scale.conv.weight` (C,1,1)、
`mixer_1d.rbr_skip.weight` (C,)、`norm_1d.rbr_skip.weight` (C,)。

**不需要 reparameterize 就能判定** —— 这是本轮补上的一个恒等式(已数值验证):

```
等效核 w = id_tensor + λ·(mixer_1d − norm_1d)
  · id_tensor  = 中心 delta            ⇒ 对称 ⇒ 反对称贡献 恰好 0
  · norm_1d    = 仅 BN ⇒ 缩放后的 delta ⇒ 对称 ⇒ 反对称贡献 恰好 0
  · rbr_scale  = k=1 ⇒ 只占中心抽头     ⇒ 对称 ⇒ 反对称贡献 恰好 0
  · rbr_conv   = k=3 ⇒ **唯一**的反对称来源
⇒ antisym(等效核) = λ·(逐通道 BN 缩放)·antisym(k=3 分支)
⇒ **k=3 分支对称 ⟺ 等效核恰好对称 ⟺ 恰好时间反转盲**
```

脚本已据此**自动回退**到 k=3 分支(`mixer_1d.rbr_conv.0.conv`),并把结果标注为**上界**
(融合后 `id_tensor` 往分母加对称质量 ⇒ 真实占比只会更小);该模式下 **DC/AC 无意义**,只读反对称占比。

**⇒ 重跑一次即可拿到判定数(`git pull` 后同一条命令,无需加参数)。**

### 7.3 这一步的判读将决定"买不买基准"

| k=3 分支反对称占比(上界)中位数 | 含义 | 决策 |
|---|---|---|
| **< 0.05** | 等效核也近似对称 ⇒ stage 1-3 基本编码不了方向;与"打乱不掉分"自洽 | **先别买基准**,R2 可先用反转敏感度自测 |
| **≥ 0.05** | 参数层面确实编码了方向 ⇒ GATE-0 的零效应是**基准测不出** | **值得买**,按 `notes/order-sensitive-eval.md` §4 走 |
