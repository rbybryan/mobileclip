# 能不能把 C2 换成别的创新点(尤其架构侧)?

**日期:** 2026-07-28 · **问题(维护者):** 仔细思考能否换成别的创新点,尤其是模型架构上的创新。

---

## 0. 结论先行

**不建议换柱子,但维护者的直觉是对的 —— C2 单柱确实是真风险。正确的动作是「加第二根柱子」,不是「换柱子」。**

三句话:

1. **换不起。** C2 有代码 + 18 项单测 + V100 八卡冒烟 + 动机曲线(1.6)+ 平凡基线已被打赢(1.8)
   + 前置闸门已结案(GATE-0)。**每一个架构候选(AC1–AC9)都是零 A/B、零测量。**
   换柱子 = 用四个月攒下的实测,换一个想法。
2. **而且 backlog 的排序刚刚失效了。** U1 导出冒烟(2026-07-27 实测)**推翻了 AC1a/AC1b/AC4
   赖以排在「主攻」的那条前提** —— 详见 §1。按新证据重排,原来的主攻要降,原来被 whitespace
   判 **Drop** 的那条要升。
3. **真正该补的第二柱是 AC5+AC9(重参数化 × 时序轴 × INT8)**,它**与 C2 互补而非竞争**,
   且 U1 刚把它的前置障碍清掉了。

## 1. ⚠️ 必须先更正:U1 推翻了架构 backlog 的排序前提

**旧前提**(`whitespace-directions.md` §0,被 round-3 §0 引为「两条绑定约束」之一):

> There is no working on-device export of the temporal model. The only export script sidesteps
> every temporal op — **which plausibly means those ops … are hard to lower to Core ML / TFLite**.

注意 "**plausibly**" —— 那是一个**推测**,从「`convert_model.py` 绕过了时序算子」推出
「时序算子导不出」。**U1 直接测了这个推测,它是错的:**

| 路线 | T∈{2,4,8,16} | 细节 |
|---|---|---|
| **ONNX** | ✅ **全 pass** | 导出 + `onnx.checker` + onnxruntime 加载推理,三步全过 |
| **Core ML** | ✅ **全 pass** | `jit.trace` → `ct.convert(mlprogram)`,~4343 个 MIL op,五段 pipeline 全过 |
| TFLite | ⏭️ 未评估 | 工具链阻塞(`litert-torch` 需 torch≥2.6,本机锁 2.5.1 给 V100 sm_70),**非模型问题** |

导出对象是**视觉塔**,架构参数与 `build_vision_encoder` 逐项一致 ⇒ **含全部时序算子**。
`convert_model.py` 绕过时序算子,是因为它是一份从 `mobileclip_s0` 搭起来的**废弃 WIP**
(`forward` 返回 `None`、不进任何 config),**不是因为那些算子导不出**。

### 后果(逐条重估)

- 🔻 **AC1a 降级。** 它的头条价值原文是「**直接产出 whitespace §0 点名的首要缺失物 —— 时序模型
  的端侧导出**」。**那个缺失物不存在了。** AC1a 的剩余价值只有峰值显存 + 一点 FLOPs ——
  而那是一个**蒸馏工程**(贵、有掉点风险),为一个能更便宜拿到的收益。**从「主攻」降为「条件项」。**
- 🔻 **AC4 失去存在理由。** 它的定位是「AC1b 掉点时的**可导出**退化」。可导出性不是问题了。
- 🔻 **AC1b 动机减半。** 「推理彻底无注意力」原来同时卖导出 + 显存,现在只剩显存,
  却仍要付 0.5–1.5 R@1 的预期代价。
- 🔺 **AC9(量化)升级。** whitespace 把它标为「Yes, for latency」需要 Step 0;**Step 0 已完成**。
- 🔺 **AC3′(因果流式)从 Drop 里捞回来重估。** whitespace 判它 `Low ROI / High risk / needs Step 0 → **Drop**`,
  三条理由里有一条已失效。

### ⚠️ 但别过度解读 —— 三件事没被证明

1. **TFLite(Android 路)仍未知。** 只有 ONNX + Core ML 有结论。
2. **导出 ≠ 快。** 真机延迟档仍在第 8 周,一个都没测。**AC9 的 NPU 兑现问题原样成立。**
3. **T 被烘成常量** ⇒ 部署是「1 份权重 → N 张图」(见 `c2-arbitrary-t.md` 墙 4)。

## 2. C2 该不该换:证据不对称

| | C2(现柱) | 任一 AC 候选 |
|---|---|---|
| 代码 | ✅ 落地,11 处硬编码动态化 + 弹性采样器 + per-T BN 工具 | ⬜ 无 |
| 单测 | ✅ 18 项全过(含 T=8 与旧代码**逐位一致**) | ⬜ 无 |
| 服务器验收 | ✅ V100 八卡冒烟三判据全过 | ⬜ 无 |
| 动机图 | ✅ 1.6 实测 T=2/4/8/16 曲线,T=2 gap = −6.1 r_mean | ⬜ 无 |
| 平凡基线 | ✅ 1.8 九臂跑完,零训练选帧**补不回**缺口 ⇒ C2 净增益无需扣减 | ⬜ 无 |
| 前置闸门 | ✅ GATE-0 结案 | ⬜ 无 |
| 新颖性 | 🟡 组合新,边距「一篇论文宽」(FluxViT) | ❓ 全部未做 prior-art kill-check |

**注意最后一行**:AC1–AC9 **没有一条做过 FluxViT 那种级别的文献 kill-check**。C2 的
「一篇论文宽」是**已知的**边距;候选们的边距是**未知的** —— 未知不等于更宽。
AC2 有 X3D/MoViNet、AC5 有 RepVGG/MobileOne、AC1 有 attention→conv 蒸馏、AC6′ 有 LoRA,
**每一条都踩在成熟文献上**,真去扫很可能扫出比 FluxViT 更近的邻居。

**时钟**:CVPR 2027 约 11 月截稿,而主时钟(H100 上的 R0)**还没起跑**。新柱子要重走
「动机图 → 平凡基线 → 闸门 → A/B」全程,那正是 C2 已经花掉的四个月。

## 3. 逐个候选:能不能当柱子?

判据:**柱子**要能单独撑起「一篇论文而非一次移植」;**配料**只能进消融表。

| 候选 | 能当柱子? | 理由 |
|---|---|---|
| **AC5** 时序多分支过参数化 | ❌ 配料(但**免费,必做**) | 「训练期并联分支、推理期折叠」= RepVGG/MobileOne 搬到时间轴。推理 +0 是真的,论文里是**一行消融**,不是一节 |
| **AC9** 重参数化-感知 INT8 | 🟡 **半根柱子** | 见 §4 —— 与 AC5 合起来才有故事 |
| **AC2** 早期时序收缩 | ❌ 配料 | X3D/MoViNet 的既有调度搬到 CLIP 侧;且硬前置 AC-b 未做 |
| **AC1a** 可分离时空注意力 | 🔻 **已降级** | 头条价值被 U1 抽走(§1);剩余=显存,却要付蒸馏成本 |
| **AC1b** 全无注意力推理 | ⚠️ 高风险,动机减半 | 唯一相对 P9 的真增量,但预期掉 0.5–1.5 R@1,且导出不再是卖点 |
| **AC4** register 瓶颈 | ❌ 失去理由 | 定位就是「AC1b 的可导出退化」 |
| **AC6′** 文本塔 LoRA | ❌ 配料 | 净新增只有 LoRA(温度已被 R1a 覆盖) |
| **AC3′** 因果 + 流式 | ⚠️ **被 GATE-0 卡死** | Step 0 虽已清,但 **GATE-0 证明模型不编码时间方向** ⇒ 因果 vs 非因果在现有基准上**测不出差别**。**无法证明收益的东西不能当柱子** |
| **AC7/AC8** 运动 token / 双线性池化 | ❌ 低优先 | note 自评「预期增益小,均可整包移除」 |
| 4 条死路 | ❌ | Mamba/SSM、delta/skip-conv、文本条件化池化、CoCa 头 —— 两轮独立判定一致,U1 不复活任何一条 |

**⇒ 没有任何单个架构候选能顶替 C2。** 最接近的 AC1a 刚被自己的实测降级。

## 4. 建议:双柱,而不是换柱

### 柱 1(不动)· C2 弹性帧数 —— 但要盯死它的两个死亡条件

publishability §2 已经写死:① **每个 T 点干净 Pareto 胜过固定 T 基线**(只打平 ⇒ 故事塌一半);
② **说得清对 FluxViT-S 的胜点**(说不清 ⇒ 框架塌方)。这两条不因换不换柱子而改变。

**低成本加固**(都已排进 ROADMAP):1.9 未见过的 T 泛化(零训练);R1 的 40-epoch 长档;
per-T BN 真 ckpt 诊断。

### 柱 2(新增,推荐)· AC5 + AC9 合并成一条:**「时序轴上的结构重参数化:训练期免费,INT8 期收账」**

这是我认为**唯一**值得现在补的架构线,理由:

1. **它是这个骨干的原生问题,不是外挂。** MobileCLIP-S2/FastViT 整个建立在结构重参数化上
   (`RepMixer`、`MobileOne` 块、时序 1D 重参数化)。`reparameterize()` 已经把
   `mixer_1d`+`norm_1d` 折叠进单个 `reparam_conv_1d`(`:762/801`)—— **并联更多线性分支再折叠
   是自然扩展,推理成本严格 +0**(AC5,note 判为「风险最低,建议最先做」)。
2. **它有一个真实且不愉快的交互,而且没人为视频-文本模型记录过。** 折叠后的核**动态范围大**,
   PTQ 会崩;要按 QARepVGG 约束分支 scale + 上 QAT(AC9)。**「训练期免费加容量」与
   「端侧 INT8」直接打架** —— 这才是有内容的架构发现,不是又一个模块。
3. **U1 刚把它的前置清掉。** 导出可行 ⇒ 端侧那半**够得着**了(whitespace 原本把它锁在 Step 0 后面)。
4. **它与 C2 互补、可同时上。** C2 管「帧数旋钮」,这条管「每帧的算子在端侧值多少」。
   两根柱子共用同一张端侧延迟表(C4),**边际成本很低**。
5. **失败也有输出。** 若 AC5 加了分支不涨点 ⇒ 一行阴性消融;若 AC9 发现 PTQ 就够用 ⇒
   那本身是端侧从业者要的结论。**没有「白做」的分支。**

⚠️ **诚实风险**:这是**效率/系统类**贡献,CVPR 主会的口味偏冷;它更适合当 C2 论文里
**独立的一节 + 端侧表**,而不是另投一篇。**所以它是「第二根柱子」,不是「第二篇论文」。**

### 备选柱 2′(非架构,但**已经测完了**)· GATE-0 的三路证据

严格说不是架构创新,但它是这个仓库**唯一已经完成、且有机制层面内容**的发现:

- **行为**:打乱 8 帧顺序 +0.1/+0.2(≈0),单帧重复 −13(阳性对照证明零是真零)
- **几何**:时间卷积核反对称占比 **0.5011** vs 随机 null **0.4999**(逐分位点吻合,n=9920)
- **参数**:时序闸门 `layer_scale_1d` 仅为同层空间 `layer_scale` 的 **6.1%**,
  且**二者同初值 1e-5**(`:636-641`)⇒ **16 倍差距是训练结果,不是初始化**

第三条是好东西 —— 它是**机制性**主张,不只是行为探针,这一点区别于 Buch et al. 那条
「atemporal probe」的既有线。**它同时也给 C2 提供了合法性**:顺序不重要、多样性重要
(1.8 + GATE-0 的调和),所以**帧数**才是对的旋钮,而不是帧顺序。

**建议:不单独成柱,写进 C2 论文的动机节** —— 它把 C2 从「我们做了个弹性模型」
提升成「我们先证明了时间轴上什么有用、什么没用,再据此设计旋钮」。

## 5. 落地动作(按顺序)

1. **改 backlog 排序**(本 PR 已做):AC1a/AC4 从主攻降为条件项;AC5+AC9 升为「柱 2 候选」;
   AC3′ 明确标注「Step 0 已清但被 GATE-0 卡死」。
2. **更正三份文件里那条被推翻的前提**(本 PR 已做):`whitespace-directions.md` §0、
   `model-architecture-improvements-round3-zh.md` §0/§2/§4、`replication-plan.md` Step 0 段。
3. **补 TFLite 那一格**(独立 venv,零 GPU)—— 它决定 Android 侧结论,也决定 AC9 的落点。
4. **AC5 开一条臂**(免费、风险最低):训练期并联 k=5 / dilated 时序分支,推理期折叠,
   验「推理逐位不变 + 训练期涨点」。**这是柱 2 的第一块砖,且不占主时钟。**
5. **AC9 的 kill-check 先做 PTQ**:折叠核直接 W8A8 PTQ,量掉多少 R@1。掉得多 ⇒ 故事成立;
   几乎不掉 ⇒ 柱 2 缩水成一行,及时止损。

**不做**:换掉 C2;上 AC1a/AC1b(等 TFLite 与真机延迟说话);碰 4 条死路;
碰任何依赖「时间方向」的方向(GATE-0 已判)。
