# 重述-融合方案：LLM 五样本重述 →（并集-验证-整合）→ 32-token 训练视图

> **范围与边界**：本文档负责 RECAPTION 桶的**完整前半段**——从「一段低质片段」到「一组可训练的
> ≤32-token 检索短视图」。它做两件事：
> 1. **重述（新前端，本次改版核心）**：用一条经过设计的中文提示，让 VLM 对同一片段独立采样
>    **五条稠密字幕**，取代原先 `better_zh` 的 2–3 条「分面」候选。
> 2. **融合**：把五条字幕分解成原子细节单元，用**跨样本一致性（support 投票）**分级、验证、整合成
>    一条「更全 + 不幻觉」的稠密稿，再降维成 ≤32-token 短视图。
>
> 它是 [`notes/data-quality-caprl-scheme.md`](data-quality-caprl-scheme.md) 的**补充件**：那份方案把 K 条
> 视图交给 `uniform` 采样消费（其 §4.4 / §5），**不做样本间的融合**；本方案专门补上「产出 K 条视图**之前**」
> 的重述+并集-验证-整合，是插在其 Pillar B 与训练视图消费之间的一个算子。
>
> **本文档是设计方案（notes/），不改训练代码**；落地按 §7 分阶段清单执行。所有引用的 arXiv id
> 均已在 2026-07 逐一联网核对（见 §9），无法证实者已显式标注。

## 0. 本次改版的动因：修掉一个自相矛盾的信任机制

### 0.1 旧方案的内在矛盾（必须先讲清）

旧版从 `better_zh` 出发——审计提示 `PROMPT` 明确要求候选「**描述不同侧面：主体动作／场景／时序**」
（`tools/data_audit/vlm_audit.py` 的 `PROMPT`、`MERGE_PROMPT` 注释亦写着 *"complementary, not redundant"*）。
但融合的**信任机制**（旧 §3.3）却是 **support 投票**：一个细节出现在 **≥2 条候选**里才「可信」。

这两者**直接冲突**：

- **投票的前提**是——多条字幕是对**同一内容的独立、冗余观测**（自一致性）。只有这样，「一致」才等于「可信」。
- **分面的构造**却把每条候选**强制推向不相交的内容**。于是几乎每个单元 `support = 1`，永远升不到
  trusted，全部落到昂贵的逐单元验真，投票先验形同虚设。旧方案实际上在**依赖候选间的偶然重叠**。

> 一句话：旧方案「用分面拿完整性」和「用冗余投票拿可信度」是**互斥**的两套假设，被硬塞进了一条流水线。

### 0.2 五样本独立重述如何一举解决

把前端改成**同一提示、独立采样五条稠密字幕**（不是五条分面），矛盾即消：

- **投票成立**：五条是 `p(内容 | 视频)` 的近似 iid 抽样，`support ∈ {1..5}` 是**真正的自一致性**估计
  （这正是 SelfCheckGPT 的构造，arXiv 2303.08896：多次自由采样，一致=可信、发散=疑似幻觉）。
- **完整性照拿**：互补性作为**采样方差 + 抽帧相位方差的副产物**自然涌现，无需强制分面；且**召回上限
  = 五条并集的单元数**，五条稠密稿的并集 ≫ 2–3 条短候选的并集。
- **门槛可标定**：`support` 从二值「≥2」升级为 5 档，可在人评集上画出 `support → precision` 曲线、
  按目标精度选阈值（§3.3、§6.3），而非拍一个「≥2」。

### 0.3 一条贯穿全文的原则：**在信任门上，精确优先于召回**

本项目目标是 MobileViCLIP 复现（arXiv 2508.07312）——**文本塔冻结、32-token**，稠密稿只是**中间产物**，
真正进对比训练的是 ≤32-token 短视图。**一个混过投票的假单元 = 一条被对比损失主动"烧录"进去的错误
图文对齐**。因此融合的失败代价是不对称的：漏掉一个真细节只是 recall 损失，采信一个假细节却会污染表征。
**信任门一律偏精确**（预期工作点 `k*=3~4`，而非 2；见 §3.3）。

## 1. 新前端：五样本独立重述（S0）

### 1.1 三条硬性设计决定（均经 VLM 方法论核验）

1. **五条独立采样，不是「一次调用吐五条」。** 让单条提示输出 JSON 五元组会**双向污染投票**：
   (a) 指令模型内建「勿重复」先验 → 真细节被改写/丢弃 → **真一致被低估**；
   (b) 第 1 条的幻觉进入上下文被 2–5 条**抄下去** → **假一致被制造**（更糟，直接在信任门制造高置信假阳）。
   故必须**五次独立调用**，条与条之间无相互条件。代价是 5× 图像 prefill，靠批处理吞掉（§7）。
2. **温度要够高，制造真方差。** 对齐后的指令模型在低温下会**模式坍缩**成五条近乎雷同的字幕，一致率
   trivially ≈100%，投票**什么都区分不了**（这是该设计最常见的失效）。默认 **temperature 0.8–1.0、
   top_p 0.9**；并**把逐单元一致率分布当作诊断量**——若绝大多数单元是 5/5 一致，说明温度过低、门没在工作。
3. **每次调用重抽 8 帧（帧相位抖动）。** 若五次共用同一组 8 帧，唯一方差源是解码噪声；若每次在同样的均匀
   分箱内用**抖动偏移**各抽一组 8 帧，则「跨不同视觉证据仍然出现」的单元才被采信——这把一致性从「模型
   自我复读」升级为「细节在视频多个视角下都在」，是**强得多的 grounding 信号**，也部分缓解 §3.5 的系统性
   偏差问题。实现上复用 `_seg_centre_idx` 加一个每样本的相位偏移，**不重抽整段、不加额外解码成本量级**。

> 直接产**中文**（不经英文）：审计已定位问题在**英文源字幕**（~16% 与画面不符、~99% 无时序），翻译健康
> （3.6%）。直接中文重述避免把英文源的问题与翻译步骤重新引回。Qwen3-VL 原生支持中文。

### 1.2 重述提示（`RECAP_PROMPT`，落地时加入 `vlm_audit.py`）

**稠密单段、非分面**，五条输出同构、便于下游对齐投票；硬编码了 OCR / 计数 / 越界推测三处护栏。

**system：**
```
你是一个严谨的视频画面描述助手。你会看到从同一段视频中按时间先后均匀抽取的若干帧画面。
你的任务是把这些画面综合成一段用于训练的中文描述，尽可能覆盖所有真实可见的信息，同时绝不编造。

严格遵守以下规则：
1. 只描述画面中清晰可见的内容。看不清、不确定、被遮挡或需要推测的内容一律省略，不要猜测。
2. 不要描述画面之外的信息：不要推断拍摄地点、时间、人物身份、情绪动机、事件的前因后果，也不要脑补画面外正在发生的事。
3. 按动作在画面中出现的先后顺序来叙述，用“先”“接着”“随后”“最后”等词表示顺序。禁止出现帧号、秒数、时间戳或“第几张图/第几帧/视频/画面/图片”这类元描述词。
4. 屏幕上的文字（字幕、标题、标牌、水印等）：只有当文字清晰可辨时，才用中文引号“”原样照抄；不要翻译、不要补全、不要猜测残缺的文字；无法辨认时直接不提这段文字。
5. 数量：只有在数量很少且能明确数清时才给出具体数字；否则用“几”“一些”“一群”“许多”等模糊量词，绝不编造精确数目。
6. 覆盖以下方面（只写真实可见的）：主体（人/物的外观、服装、颜色等特征）、主体的动作及其先后、场景与背景环境、屏幕上的文字。如果某一方面在画面中不存在，就完全不要提它。
7. 输出一段连贯、信息密集的中文，不要分点、不要标题、不要开场白或结束语，只输出这段描述本身。
```
**user：**
```
请综合这些画面，按上述规则输出一段中文描述。
```

设计对应约束：规则 1–2 收住越界/无中生有的**系统性幻觉面**（§3.5）；规则 3 给「事件顺序而非时间戳」
（Qwen3-VL 无真时间码，否则会臆造 "0:03" 之类标记）；规则 4 针对 **OCR 弱点**强制「原样照抄或不提」，
禁掉模型「补全残字」的冲动；规则 5 针对**计数弱点**允许优雅降级到模糊量词而非自信写错的整数；规则 6 在
**不分面**的前提下保住主体/动作/OCR/场景四维覆盖，并显式禁止「清单逼出的空槽填充」幻觉。

> 与旧 `better_zh` 的关系：旧的 2–3 条分面短候选是本设计在 `N=3 且分面` 下的退化特例，投票信号弱。
> 已产出的 `better_zh` 可作兜底输入跑通流水线，但**新数据一律走五样本重述**（§7 迁移说明）。

## 2. 借鉴的方法（arXiv id 均已核对，见 §9）

| 作用 | 方法 | 我们移植的点 |
|---|---|---|
| **投票的理论根** | Self-Consistency（arXiv 2203.11171） | 多次采样、以样本一致性作证据。**注**：原设定是「推理→单一离散答案」，本方案只借其**根思想**，非字幕方法 |
| **投票的直接依据（主引用）** | **SelfCheckGPT**（arXiv 2303.08896） | 把自一致性推广到**无唯一正解的自由生成**：采样多条、用样本间一致性作**幻觉分**。我们的原子单元 support 投票 = 结构化、离散化的 SelfCheckGPT |
| **原子单元分解** | **FActScore**（arXiv 2305.14251） | 把一段生成**拆成原子事实**、逐条核其是否被可靠证据支持——正是我们 S1 分解 + S4 逐单元验真的度量骨架 |
| **系统性偏差的警告** | Visual Contrastive Decoding（arXiv 2311.16922） | 指出 VLM 幻觉源于**统计共现偏差 + 单模态语言先验**（"厨房⇒有人做饭"）——这类是**低方差**幻觉，投票会给它**最高**置信（§3.5） |
| **融合后验收（双向）** | OwlCap / CSER（AAAI'26，arXiv 2508.18634） | 字幕拆原子单元、unit-to-set 匹配 + **双向 precision/recall**——我们 S6 验收的核心度量 |
| **逐 query 验真** | CCCaption（CVPR'26，arXiv 2602.21655） | 把字幕拆成 sub-caption query 逐条验真、罚幻觉——我们 S4 单例验真的手段 |
| **并集融合骨架** | Scene-Graph Consolidation（arXiv 2502.16427） | 各字幕解析成场景图、Hungarian 对齐同一实体、**合并=属性并集**、迭代整合；无需微调——我们 S2/S5 的算法骨架 |
| **重述-配 CLIP 数据的血统 + 整合动机** | LaCLIP（2305.20088）· **CapsFusion（2310.20550）** · Recap-DataComp-1B（2406.08478）· InternVid（2307.06942） | CapsFusion 明确证明「LLM **整合** 原始+合成字幕」优于任一单独来源——**直接支持我们的整合步（S5）** |
| **效用选择器（限定用途）** | CapRL / CapRL++（ICLR'26 arXiv 2509.22647 / arXiv 2606.09393） | 无视觉 LLM 答 MCQ 的准确率。**用途须精确**：它度量字幕的**信息量/效用**，**不是 grounding**——一条自信的系统性幻觉照样可答 MCQ。故只用它排**完整性**，**不**作事实性验真门 |
| **对照（勿误引）** | CIDEr（arXiv 1411.5726） | 经典「consensus」指**多条人工参考**间的一致（评测用），**不是**从单模型采样。仅作**对照**引用，非本方案先例 |
| **可选偏好训练（F3）** | SynPO（arXiv 2506.00835） | 若把「融合稿 ≻ 单条」做成可训偏好信号时的 DPO 侧参考 |

> **诚实缺口**：captioning 领域**没有**一篇「采样 N 条 + 原子单元聚合」的经典对标论文来充当
> self-consistency 之于 reasoning 的角色。本方案是 **SelfCheckGPT（样本一致）+ FActScore（原子事实核验）**
> 的合理综合，请如实这么标注，勿夸大为「已有成熟方法」。

## 3. 融合与幻觉控制（核心）

### 3.0 总览：CFU（Consensus-Fusion & Utility-verify）

```
S0 五样本独立重述  C = {c1..c5}   (同一提示, temp 0.8–1.0, 每样本抖动抽 8 帧)
        │
 ┌──────┴───────────────────────────────────────────────┐
 │ S1 分解  每条 → 原子细节单元 u=(主体/属性/动作/文字/场景/顺序) │  (FActScore 原子事实 / SG 节点)
 └──────┬───────────────────────────────────────────────┘
 ┌──────┴───────────────────────────────────────────────┐
 │ S2 对齐+计票  跨样本合并同义单元, 记 support ∈ {1..5}     │  (嵌入/Hungarian 匹配, 取并集)
 └──────┬───────────────────────────────────────────────┘
 ┌──────┴───────────────────────────────────────────────┐
 │ S3 分级（阈值 k* 经标定, 预期 3–4, 分类别）              │
 │   trusted  : support ≥ k*   → 采信                      │  (自一致性)
 │   low      : support <  k*   → 送验真                    │  (SelfCheckGPT 低一致=疑似)
 └──────┬───────────────────────────────────────────────┘
 ┌──────┴───────────────────────────────────────────────┐
 │ S4 验真  异质验真器对 low + 高风险类别单元逐个核验       │  → 通过者升 verified
 └──────┬───────────────────────────────────────────────┘
 ┌──────┴───────────────────────────────────────────────┐
 │ S5 整合  LLM 把 {trusted ∪ verified} 融成 1 条稠密稿 f   │  (闭集约束, 保事件顺序; CapsFusion 式整合)
 └──────┬───────────────────────────────────────────────┘
 ┌──────┴───────────────────────────────────────────────┐
 │ S6 验收  双向 precision/recall + 幻觉率闸门 (>10% 回退)  │  (OwlCap CSER 风格)
 └──────┬───────────────────────────────────────────────┘
 ┌──────┴───────────────────────────────────────────────┐
 │ S7 降维  由 f 派生 K 条 ≤32-token 检索短视图 (§4)        │  → 进 captions 列表训练
 └────────────────────────────────────────────────────────┘
```

### 3.1 分解到原子单元（S1）
一次 LLM 调用把**每条**样本拆成结构化单元，类型集：
`subject / attribute / action / onscreen_text / setting / temporal_order / count`。
`onscreen_text` 与 `count` **单列**——它们是 §3.5 的高风险类别，需单独闸门。
```jsonc
// c1="一名男子先在厨房切菜，接着把菜倒入锅中" 的分解
[{"type":"subject","text":"一名男子"},{"type":"action","text":"切菜"},
 {"type":"setting","text":"厨房"},{"type":"action","text":"把菜倒入锅"},
 {"type":"temporal_order","text":"先切菜后倒入锅"}]
```

### 3.2 跨样本对齐 + 计票（S2）
所有样本的单元入一个池做**同义合并**：文本嵌入余弦 >τ（初值 0.85）或同 `type` 下 LLM 判同义 → 合并为一，
`support = 覆盖到它的样本数 ∈ {1..5}`。合并取**属性并集**（Scene-Graph Consolidation：「红色卡车」+「卡车在左侧」
→「左侧的红色卡车」）。产出去重单元集，每单元带 `support`。

### 3.3 自一致性分级 + 阈值标定（S3）——**信任规则**
- **trusted（support ≥ k\*）**：k\* 个独立样本一致 → 采信。**k\* 不是常数、要标定**（§6.3）：在视频接地的
  人评集上对每个 k∈{2,3,4,5} 算 trusted 规则的 precision/recall，**按目标精度选 k\***。因 §0.3 的不对称代价，
  预期工作点 **k\*=3 或 4**；`k=2` 会漏放太多随机单例，明确判定为过松。
- **low（support < k\*）**：送 S4 异质验真；未过者**丢弃**（宁漏勿错，召回损失由 §3.5 的 recall 项监控）。
- **分类别阈值**：`onscreen_text` / `count` 的「一致率→正确率」关系与其它类别不同（高一致≠高可信，§3.5），
  应设**更高的 k\*** 或**无论 support 一律送异质验真**。

### 3.4 高风险单元的额外闸门
- `onscreen_text`：VLM 文字幻觉高，**且系统性**。规则：**必须过 OCR 引擎复核**（异质，见 §3.5）才进融合稿；
  否则整条丢弃，不「猜一半」。
- `count`：VLM 计数公认弱。数量词一律降级为**非数值措辞**（「几个人」）或走异质计数复核，绝不直接采信单例数字。

### 3.5 诚实的边界：一致性只抓随机幻觉，抓不住系统性幻觉
> 这是本方案**最重要的一条自我批判**，直接决定 S4 验真器**必须异质**。

多样本一致性抓的是**高方差（随机）幻觉**——模型内部不确定、样本间闪烁的细节；对**低方差（系统性/先验驱动）
幻觉**——模型每次都以同样方式误读——则**完全失明**：五条会一致同意，投票于是给它**最高**置信。系统性幻觉
源于统计共现偏差与单模态语言先验（arXiv 2311.16922，如「办公桌⇒在打字」「厨房⇒在做饭」）。换言之，
**对系统性偏差单元，同模型的有效独立样本数≈1 而非 5，一致性会高估其可信度。**

**推论——S4 必须用与字幕器"沿其偏差不共享的轴"相异的验真器**：
- **物体存在性** → 用 **GroundingDINO**（本仓库 anticipatory-foveation 线已在用）开放词表检测，确认「trusted 物体
  单元」在帧里真能被检出——这正是同模型自查给不了的、非语言先验的异质证据。
- **屏幕文字** → 用**真正的 OCR 引擎**做验真器，而非让 VLM 自己跟自己投票。
- **多体关系 / 越界推断** → 用**另一家族的 VLM**（异构）二次核验。
- **CapRL MCQ 效用**（2509.22647）**只测信息量、不测 grounding**——自信的系统性幻觉照样可答 MCQ，**不得**当事实门；
  只用来在 §3.6 里排「哪条更全」。

> 一句话：**一致性负责随机层，异质验真负责系统层**；`low` 单例**与** bias-prone 类别的「一致但可疑」单元，
> 无论 support 高低都要过异质验真。

### 3.6 整合 + 验收（S5–S6）——闭集融合 + 双向验收
- **整合（S5）**：只给 LLM `{trusted ∪ verified}` 单元表，指令：「**仅用下列事实**写一条通顺中文字幕，
  **不得新增任何未列出的细节**（闭集/抽取式，非生成式补全），保留事件先后措辞」。闭集约束是防 LLM 在
  「润色」时再造幻觉的关键（CapsFusion 证明这种「整合」优于任一单来源）。
- **验收（S6，OwlCap CSER 双向）**：
  - **precision（压幻觉）**：把融合稿 `f` **反向再分解**，逐单元查是否 ∈ 输入单元集；出现输入里没有的 =
    融合期新造幻觉 `hallu_unit`。`precision = 1 − |hallu_unit| / |f 的单元|`。
  - **recall（保完整）**：`recall = |f 覆盖的 trusted∪verified 单元| / |trusted∪verified|`。
  - **幻觉率闸门**：片级 `1−precision > 10%` → 该片**回退最佳单条**（§3.7）；批级过闸 → 收紧 τ / 提高 k\* /
    改走更硬验真 / 回退整批。

### 3.7 回退策略（融合不是免费的）
每片留一条**安全底**：融合稿未过验收则回退为**最佳单条样本**——用**片-帧 CLIP-score**（复用仓库冻结
MobileCLIP-S2 图像塔，异质于字幕器）在 `C` 内选最高分那条；若要更强，用 CapRL 效用排完整性但**仅在已过
grounding 验真的候选间**排。**保证融合永不使某片变差**。

## 4. 适配 32-token 训练窗（与 caprl-scheme.md §4.4 对齐）

融合稿 `f` 通常超 32 token。**不把 `f` 直接投喂对比模型**（会被截断成半句、且训练/测试长度失配，见 §8）。
`f` 的定位是**验证/记录产物**（人审、留痕、算 recall），训练视图由它**派生**：

1. **主路：重提示派生 K 条短视图**。给 LLM `f` + 其单元集，指令「产出 K 条 ≤30 字检索风格短句，**每条覆盖
   不同的 trusted/verified 单元子集**（一条主体+动作、一条含画面文字、一条场景），彼此互补」。K 条并集≈f 的
   信息，符合 CapRL 效用观。（**注意**：分面只发生在**这里、对已验收的融合稿**——此时不再需要投票，故分面
   无害；前端 S0 坚持不分面正是为了保住投票。）
2. **兜底：句级切分**。省一次生成时，对 `f` 按句切、逐句成一条，超 32 token 的句子压缩或丢弃。
3. **短标签副产物**：`subject/action/setting` 单元直接吐成 `tags`（超短视图），喂 caprl-scheme.md Pillar C，
   天然满足 32-token、贴近 MSR-VTT 短查询分布（§8 护栏）。

> **写回训练 JSON（向后兼容 caprl-scheme.md §6.1 schema）**：
> ```jsonc
> {
>   "video": "clip.mp4",
>   "caption": "<原上游字幕, 保留为采样视图之一>",       // §8 长度护栏
>   "captions": ["短视图1(主体+动作)", "短视图2(含画面文字)", "短视图3(场景)"], // ← S7 产出
>   "fused_dense": "<融合稿 f, 仅记录/验证, 不进对比训练>",  // 留痕, 不采样
>   "fuse_meta": {"precision":0.94,"recall":0.88,"fallback":false,
>                 "K_from_fusion":3,"n_samples":5,"k_star":3}
> }
> ```
> loader 侧无需改动：`captions` 列表已被 `dataset/pt_dataset.py:176-189` 的 `uniform` 采样支持；
> `fused_dense`/`fuse_meta` 是新字段，训练时忽略即可。`apply_buckets.py` 已支持把融合稿当主 caption
> （`--merged`），把原 zh + 候选挂 `captions`（现有 `merged_primary` 计数逻辑，line 181-189）。

## 5. 保留时序角度（与 caprl-scheme.md 的时序闭环一致）

融合是「取并集」，若不约束会把多条压成一句无序静态描述，抹掉事件顺序。四条护栏：

1. **`temporal_order` 作为一类单元**：S1 显式抽「先…然后…最后」措辞；任一样本含顺序即进单元集，S5 **必须保留**。
2. **重述提示已强制事件顺序措辞**（§1.2 规则 3），S5 整合指令再复述一次「多动作用之前/然后/之后串联」——
   与 caprl-scheme.md §5 的「事件顺序措辞而非绝对时间戳」一致（模型只见均匀 8 帧、无时间戳）。
3. **不引入时间戳**：融合稿一律 strip 绝对时间戳，顺序只用相对措辞承载。
4. **喂给硬负**：派生的含顺序短视图直接作 caprl-scheme.md §5 `hard_negs` 的顺序反事实扰动源
   （「坐下然后起立」↔「起立然后坐下」），把融合与既有时序闭环接上。

### 6.2 分阶段（ROI 从高到低，均可提前止损；接在 caprl-scheme.md P0 之后）

| 阶段 | 内容 | 训练？ | 新增/改动 | 验收门 |
|---|---|---|---|---|

**先做 F0**：产出数据即可用人审确认「五样本重述+trusted 融合是否真比单条更全」这个前提，并**在 F0 里就把
k\* 标定出来**——后续所有阶段都依赖这个阈值。

### 6.3 支持阈值标定协议（把「≥2」换成可测的 k\*）
1. 抽 ~150–300 片，跑完整前端到原子单元，记每单元 `support`。
2. 标注者对每个原子单元标 **present/absent（对照真实视频，不是 8 帧）**——如此**同时测到抽帧盲区误差**
   （模型只看 8 帧，真值以视频为准）。
3. 对每个 k∈{2,3,4,5} 算「trusted ⟺ support≥k」相对标注的 **precision/recall**，画 P/R 折衷曲线。
4. **按精度选 k\***（§0.3 不对称代价 → 预期 k\*=3~4）。
5. **按类别分层**（主体/动作/画面文字/场景/数量）：OCR 与计数的 support→accuracy 关系不同，设**类别专属 k\***
   或对其**无论 support 一律走异质验真**。
6. **把一致率分布本身当诊断报出**：若众数单元是 5/5，说明温度过低、门没在区分（§1.1-2）。

> 统计注记（须写进文档）：投票的置信解释假设每样本是**独立** Bernoulli 检测器；共享系统性偏差使样本相关，
> 有效 N < 5，对 bias-prone 单元一致性**高估**置信——这也是标定集**必须视频接地**而非模型接地的原因。

### 6.4 关键消融（让「五样本重述+融合有用」成为**可证伪假设**）
同一 curated 子集、**等数据预算 + 等算力**，只换字幕来源，比 MSR-VTT-1k / K400 检索：

| 臂 | 每片训练视图来源 |
|---|---|
| **A. uniform-K（对照，=caprl-scheme.md 现状）** | 五样本重述直接 uniform 采样（不融合） |
| **B. best-single** | 只保留 §3.7 选出的最佳单条 |
| **C. fusion（本方案）** | S7 派生的 K 条融合短视图 |
| **C′. fusion+tags** | C 再加 `tags` 超短视图 |

**判据**：C 需**同时** ≥ A 与 ≥ B 才算「融合成立」；若 C ≈ A，则融合的额外算力不值，回退 uniform-K。
**附加消融**：(i) 样本数 **N∈{3,5,8}** 对 trusted 稳定性与下游的影响；(ii) 阈值 **k\*** 的敏感性；
(iii) **温度**（0.3 vs 0.9）验证「低温坍缩→投票失效」；(iv) 分**短/长查询**子集报 R@1（§8 长度失配）。

## 7. 成本与护栏

**算力粗估（对 RECAPTION 桶的 N_r 片，非全量 1M）**：
- **S0 五样本重述（新增主成本）**：每片 **5 次 VLM 生成**（8 帧输入）。是旧「1 次 better_zh」的 5×，但
  **仅对 RECAPTION 片**、且可批处理；若后端缓存视觉塔前向（帧特征算一次、解码 5 次），实际开销远低于朴素 5×。
  N_r=200k、Qwen3-VL-8B+vLLM ≈ 1–2 片·样本/秒/卡 → **数百卡时**量级。**N 是成本/鲁棒旋钮**：默认 5，
  预算宽可 8–10（标定曲线更平滑、稀有真单元更稳），**不低于 5**（N=3 只有 2/3、3/3 两档，太粗）。
- **S1 分解 + S2 对齐 + S5 整合**：纯文本 LLM，每片数次短调用，可忽略。
- **S4 异质验真**：GroundingDINO/OCR 是轻量专用模型，比 VLM 便宜；二号 VLM 仅对高风险关系单元开、按需限流。
- 总体仍比 caprl-scheme.md §7 的重写步小一个量级——融合是重写的**后处理**，不是重复重写。

**护栏（honest limits）**：
- **训练/测试长度失配**：MSR-VTT 查询 ~9 词短句；融合稿更长更全。三重对冲同 caprl-scheme.md §8：S7 本就产
  ≤30 字短视图、`tags` 超短视图、原上游字幕保留为采样视图之一。消融 §6.4 必须分短/长查询报点。
- **系统性幻觉盲区**（§3.5）：一致性抓不住的偏差层，靠异质验真兜；**bias-prone 类别一律异质**。
- **温度坍缩**（§1.1-2）：低温=投票失效；用一致率分布诊断。
- **验真器同源风险已按 §3.5 结构性排除**：验真器换族/换模态（GroundingDINO / OCR / 二号 VLM），不再是
  「Qwen 验 Qwen」。这是相对旧版最实质的鲁棒性提升。
- **冻结文本塔的收益上限（诚实存疑）**：文本塔 `freeze_text=True`。「更完整的字幕」能否被一个冻结的 32-token
  文本编码器转化为更好的检索表征本身不确定——若 MobileCLIP-S2 文本嵌入对「多细节 vs 少细节」短句本就近似
  饱和，融合的信息增益可能在编码端被抹平。这正是 §6.4 消融要回答的核心，**不预设结论**。
