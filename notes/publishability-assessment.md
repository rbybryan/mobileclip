## 0. 现实校准(先摆正,别被计划的乐观语气盖住)

到今天为止,全量 10M 的 H100 训练**一步都没跑**(`notes/live/from-server.md` 无回报)。
已落地的只有:

- ✅ B0 基线复现成功(MSR-VTT t2v R@1=**42.50**,对上论文,见 `experiments/README.md` §3.4);
- ✅ V100/10k 试点验证了**链路**(`experiments/pilot_10k_results.md`);
- ✅ 实验框架 + 组件开关 + 卫生修复就绪(PR #64 起)。

⇒ **C1–C4 没有任何一项拿到过「比基线好」的数字。** 所以「优化程度够不够」现在
**无法回答**——不是不够,是**还没优化出结果**。手里是「想法 + 验证过的管线 +
复现的基线」,离「有优化程度」还差**整个主实验**。

## 1. 创新点评估(评的是计划的新颖性)

| 贡献 | 新颖性 | 判断 |
|---|---|---|
| **C2 时间维弹性蒸馏** | **组合新(07-23 收窄)** | 仍是唯一撑得起「一篇论文而非一次移植」的点,但 FluxViT(ICCV'25,arXiv:2503.14237)已做「弹性采样×InternVideo2-1B 蒸馏×多预算零样本检索」——C2 的可声称空间收窄为**帧数旋钮×移动端卷积混合双编码器×固定 T=16 冻结锚点×端侧延迟实测**四格组合(`plan-review-upgrades.md` §3.1)。成败仍押在:单个弹性 ckpt 每个预算点 Pareto 压过固定 T,**且说得清对 FluxViT-S 的胜点**。**未验证。** |
| **C1 视频数据强化(DR)** | 中 | 「图像侧 DR 无视频版」站得住,但单独看=把 MobileCLIP2 配方搬到视频,易被评 incremental;靠 C2 当挡箭牌。 |
| **C3 sigmoid 多正例 + 注意力池化** | 低 | 已知技术,只值一张消融表,非卖点。 |
| **C4 端侧延迟表** | 加分项 | 移动端真机延迟是硬通货,但 P9 标注**联合注意力可能导不出**=延迟表前置风险。 |

**结构判断:** 创新集中在 C2 一根柱子。C1 是「合理但增量」,C3 是「配料」。典型的
**单点创新 + 扎实工程**——成败取决于这根柱子撑不撑得住。

### 1.1 🔺 2026-08-03 修订提案:C2 → **C2-2D**(条件升级,采纳 §11.8-N1)

**提案**:把 C2 的弹性主张从 1D(帧数)升级为 **2D(帧数 × 分辨率),含混合分配** ——
「一份移动端 ckpt,任意 (T, R) 预算格点,且同一段视频内允许逐帧混合分辨率」。
这是**加厚唯一的柱子**,不是另立第二根;C2 的评测纪律、Pareto 判据、端侧延迟要求全部继承。

**为什么这格是空的**(2026-08 两轮网扫 + 已知近邻):

| 近邻 | 它做的 | 没做的 |
|---|---|---|
| FluxViT(ICCV'25,已知最强邻) | token 数弹性 × 蒸馏,transformer 原生 | 卷积塔没有 token 轴;R 旋钮是另一条机制 |
| FlexiViT(CVPR'23) | 单 ViT 的 patch-size 弹性(图像分类) | 视频、检索、T 轴、混合分配都没有 |
| AdaFocus 系(ICCV'21+) | **学习式**逐帧空间预算策略(识别任务) | 动态 policy ≠ 静态弹性合同;非检索、非单 ckpt 契约 |
| ElasticTok / AKS / VideoTree(2025-26) | token 分配 / 查询自适应关键帧(Video-LLM) | 全在 token/LLM 侧 |

⇒ 新颖性等级与 C2 本体相同(**组合新**),主张要框死在空格子里:
*static conv-native single-ckpt (T×R) elastic contract + mixed per-frame allocation,
for on-device video-text retrieval, with measured per-budget latency*。

**升级的四个条件(缺一不升,按序验)**:

1. **免费评测闸门先赢**(零训练,分钟级,`verification-tier` §11.8-N1 阶梯①):
   iso-MACs 格点上混合分配 > 均匀分配,且 2D 格点最优 > 1D 最优。输 ⇒ C2 保持 1D,零损失。
2. **elastic-(T,R) 训练 ckpt 拿住逐预算 Pareto**(§2 清单第 1 条的 2D 版 ——
   那条本来就写着「这就是论文本身」)。顺带红利:多 R 训练让 BN 见全分辨率,
   P7 的「未校准只能当趋势」旧债从根上清掉;万一 BN 仍漂,`per_t_bn.py` 的
   per-budget BN bank 是现成的兜底。
3. **related-work 定位先写后投入**:上表四族点名,把主张框进空格子(防审稿人一句
   「FlexiViT 已做」翻车 —— 回答是:卷积混合架构没有 token/patch 轴,R 旋钮 + 混合
   分配是移动端原生的那条路)。
4. **端侧延迟按预算点实测**(§2 既有要求,格点从 4 个变 ~8 个,量测成本线性)。

**风险与降级路径**:闸门 1 输 ⇒ 降级为「2D 网格弹性」(仍可写,弱一档);
全减法闸门(§11.7-2)失败 ⇒ 混合分配要走两组前向的丑实现(可测但故事变钝)。
两条降级都不伤 C2 本体。

## 2. 能发顶会吗:必要条件清单(缺一即降级)

目标 CVPR 2027(约 2026-11 截稿)/ 备选 ICLR 2027。以下**全部兑现**才是顶会级:

- [ ] **C2 干净 Pareto 胜利**:同一弹性 ckpt 在 T=2/4/8/16 每点 ≥ 对应固定 T 基线(等 FLOPs)。**这就是论文本身**;只「打平」则故事塌一半。
- [ ] **C1 DR 兑现图像侧量级**(+2–5 点),否则主线收益压不过「增量」质疑。
- [ ] **端侧延迟表真能导出**(过 P9;07-23 起转换性冒烟已提前到 ROADMAP 1.5),
  对比 MobileViCLIP / InternVideo2-S/B;TempMe(微调协议)单独列区。
- [ ] **R0 全量复现 MobileViCLIP 量级**(尚未在 H100 验证)。
- [ ] **(07-23 新增)对 FluxViT-S(ICCV'25,24M)有明确胜点**:等 GFLOPs 精度
  或端侧延迟至少一项正面赢,且差异化四轴(帧数旋钮/移动端骨干/固定 T 锚点/
  端侧实测)在论文里立得住——说不清即 C2 框架塌方。

**拉高天花板的杠杆:** 弹性模型低 T 端若明显掉点 → 触发 R4(P7 非对称帧编码)做
组合 Pareto 面,从「一个技巧」升级为「一套帧预算方法论」;CapRL 合成字幕 +
时序难负例(几乎免费)加厚消融。

## 3. 真实风险

- 领域不空:efficient video-text 有 TempMe、各类 token merging 在竞争;弹性推理的
  「新」必须靠**实测 Pareto 图**说话,讲故事挡不住。
- **全押在尚未运行的主实验上**,算力默认 4×H100;R0 复现、教师推理成本、导出
  任一环出问题都会连锁。
- C1+C3 单独**发不了顶会**——它们是 C2 的支撑而非主张。

`ROADMAP.md` 第三线 3.2)。有了 R0 复现 + R1 组件方向,才谈得上评估优化程度。
