## 0. 四条结构性事实（先证明，再数值验证）

四条都是**这个模型**的性质，不是一般性断言。每条都在机器精度下（`~1e-15`）做了数值检查，
检查可由下文片段复现。

记 `z_1..z_T ∈ R^512` 为逐帧嵌入（T=8），`v = mean_t z_t` 为视频嵌入
（`FastViT.forward:1377-1384`，`models/mobileviclip_small.py`）。

### F1 —— 读出头**无条件**时间盲

`v` 是一个**集合**的均值。均值对**任意**置换不变，与轨迹形状无关——直的、弯的、任意的都一样。
已验证：`‖mean(Z) − mean(reverse(Z))‖ = 3.8e-15`。

**推论。** 本模型全部的时序顺序敏感性都必须在 **backbone 内部**制造出来，并作为一个**clip 级
全局信号**"走私"进**每一帧**的嵌入里——因为只有被所有帧共享的成分才能在平均后幸存。候选通道
只有两个：stage 1–3 里的逐通道时间 `Conv1d(k=3)`，以及 stage-4 的 `temporal_embedding`
（`:1096` 定义，`:1105` 施加）。F2 将说明第二个通道不可能起作用。

### F2 —— **加性**位置码被精确抹掉，只有**乘性**绑定能幸存

分解 `z_t = c_t + p_t`（内容 + 加性位置码）。于是 `mean(z) = mean(c) + mean(p)`，而 `mean(p)`
是一个常量，**与"哪个内容坐在哪个位置"无关**。把内容跨位置置换，`v` 完全不变。

已验证：加性打标 → 内容置换与反转下变化 `1.9e-15`；乘性绑定（按帧序号相关的角度旋转二维平面）
→ 变化 `11.0`。

**推论，而且直指我们的代码。** stage 4 是**加性**地施加时间码的：
`x = x + resize_temporal_embedding(self.temporal_embedding, t)`（`mobileviclip_small.py:1105`）。
按 F2，它对池化后嵌入的顺序敏感性的贡献**恰好为零**——除非经由下游非线性，那是一条间接的、
未被测量的通道。这是比第一轮更锐利的瓶颈 (c) 陈述：**模型没有显式的 what×when 合取通道。**

### F3 —— 均值湮灭轨迹的**一阶项**，而把它捞回来是免费的

写 `z_t = s + (t−t̄)·u + r_t`。由于 `Σ_t (t−t̄) = 0`：

```
mean_t z_t  =  s + r̄          ← 速度 u 的贡献恰好为零
```

已验证：`r=0` 时 `‖mean(Z) − s‖ = 2.8e-15`。而 `u` 的最小二乘估计是一个**常数权重的固定加权和**：

```
û = Σ_t (t−t̄)·z_t / Σ_t (t−t̄)²      其中 Σ_t (t−t̄)² = T(T²−1)/12   （T=8 时 = 42）
```

**以及必须履行的 T1 披露——这是精确恒等，不是类比。** Approximate rank pooling
（Bilen 等，*CVPR* 2016）用 `α_t = 2t−T−1`；T=8 时 `α_t = 84·w_t`，已精确验证。
**最小二乘轨迹斜率*就是* approximate rank pooling，相差一个尺度因子。** 本篇任何提案都必须
主动先讲这一点，而不是等审稿人发现。

### F4 —— 检索损失在帧残差子空间上**恰好平坦**

因为损失只经由 `v` 依赖 `{z_t}`：

```
∂L/∂z_t = (1/T)·Jᵀ·(∂L/∂v)          ← 对每个 t 完全相同
⇒  对任意零和扰动 Σ_t δ_t = 0：   Σ_t ⟨∂L/∂z_t, δ_t⟩ = ⟨g, Σ_t δ_t⟩ = 0
```

**两个推论，都很严重，且都与第一轮的直觉相反。**

1. **"对比损失会阻止塌缩"在这里是错的。** 它钉住的是**均值**。帧残差塌缩（所有 t 上 `z_t → z̄`）
   对主损失的代价**恰好为零**——它不是风险，它是一个自由方向。任何 slowness / straightening
   风味的辅助损失，其**全局最优**就是塌缩，且没有任何力量往回推。
2. **纯定义在残差结构上的辅助损失，与检索目标一阶正交。** Straightening、时序去相关、
   潜空间下一步预测，全都活在这个零空间里。

还有一条通往退化解的廉价架构捷径：逐通道时间卷积核 `[a,b,c]` 只要直流增益 `a+b+c = 1`，
就是一个纯时间低通——**衰减残差的同时精确保留时间均值**。几十个核权重就够了。这正是 §2
的审计要测**核的 DC/AC 比**的原因。

**重要的适用边界（不要过度套用 F4）。** F4 杀死的是*定义在残差子空间上的损失*。它**不**杀死
那些改变池化向量本身的架构改动——重加权或增广的读出会**直接**改变 `v`，对损失完全可见。
A1（惊奇池化）、A2（分级窗）与下文的 R2 都属于**可见类**。

## 1. 测量危机 —— 我们的基准看不见时序结构

这是四份评审各自独立得出的第二条发现，而且它卡住了一切。

- **一帧就够了。** 单帧训练 + 帧集成的模型，在 MSR-VTT / DiDeMo / ActivityNet 检索上
  追平甚至超过多帧模型（Lei, Berg & Bansal，*ACL* 2023，"Revealing Single Frame Bias"）；
  Buch 等（*CVPR* 2022）的无时序探针在整套标准基准上都有竞争力。
- **本该一锤定音的数字：BLIP —— 一个纯图像模型 —— 据报在 MSR-VTT 零样本 R@1 达到 ~43.3，
  高于我们锁定的基线 42.50。** 我们的头号基准目前是被一个完全没有时序建模的模型赢下的。
- **MSR-VTT 测试视频里只有约 10% 是时序相关的**（RTime，*Reversed in Time*，ACM MM 2024）。
  帧打乱在许多模型上的贡献都接近零。
- **冻结的 video-CLIP 编码器在"时间方向"上处于随机水平。** 已报道的探针把帧中心编码器
  定在 49.5–50.7%，而 InternVideo2 在做完 CLIP 式语言对齐后**掉到 ~49.5%** ——
  也就是说，VTC 对齐**侵蚀**时间方向信息。

**两个后果。**

1. **任何只在 MSR-VTT/DiDeMo/ANet 上评测的时序改动，按构造就会量出零**，而我们会错误地
   得出"这个想法失败了"的结论。顺序敏感的评测是**强制**的：**RTime（尤其 RTime-Binary）**、
   SSv2-template/label 检索、Vinoground、TemporalBench。SSv2-MC 可以留着，但**别再**把它当成
   时序证据——174 个模板上的多选会泄漏外观线索。
2. **RTime-Binary 有解析可知的零假设。** 如果池化嵌入对时间反转不变，那么一个视频和它的
   倒放会映到**完全相同**的向量，排序就是抛硬币——**恰好 50.0%**，而不只是"表现差"。
   这把一个含糊的问题变成了一个**零假设已知**的二元判据，是我们手上最干净的证伪器。

### 1.1 决策阈值很可能低于我们的噪声地板

MSR-VTT 1k-A 有 n=1000 条查询，因此 R@1≈45% 处的二项标准误约 **1.6 个点**。配对 A/B 能抵消
其中很大一部分，但**训练随机种子的方差抵消不掉**：R@1 上预计约 ±0.5–1.0，累到 R-Sum 就是
**±1.5–3**。

`notes/paper-plan.md:127` 仍写着 **"≥ +0.3 R-Sum"** 的保留判据。同一文件 §227-229 已经收紧过
（多基准、双口径、<0.5 的判定需第二个种子），但两处陈述互相矛盾，而且**收紧后的那条仍可能
功效不足**。

**行动：用不同种子把锁定基线在全量上再跑一次。** 这一次跑动能把之后每一条实验臂从"轶事"变成
"证据"。在那之前，宁可用**多数据集符号检验**（MSR-VTT + DiDeMo + MSVD + ANet，双方向，
8 个格子里 ≥6 个同号）也不要用任何单一数字阈值——八格一致的 +0.4，远比 MSR-VTT 上单个 +1.2
更有说服力。

## 2. GATE-0 —— 时间维容量审计（零训练，先于一切）

四份评审都独立提出了它。它只是几个小时的测量，却能杀死或改道一整类工作，而且无论结果如何
都产出一张论文图。

### 2a. 静态审计 —— 只看 checkpoint，不用 GPU，不用数据

`experiments/temporal_capacity_audit.py`（新增，自带自测）读入一个 checkpoint 并报告：

- **`‖temporal_embedding‖`** 及其逐位置离散度。它是**零初始化**的（`:1096`），所以如果训练
  从未推动它，stage 4 对帧就是置换等变的，按 F1 贡献为零。*（按 F2，即使它非零贡献也≈零，
  因为它是加性的。两个数字都值得有。）*
- **时间核反对称占比** `‖w − flip(w)‖ / (2‖w‖) ∈ [0,1]`。时间反转把 `[a,b,c] → [c,b,a]`，
  所以**对称核精确地对反转盲**。这是"时间之箭容量"的直接度量：0 = 反转盲，1 = 纯差分算子。
- **时间核 DC/AC 比** `|Σw| / Σ|w|`。→1 意味着纯低通，即 F4 的塌缩捷径已被走通、帧残差正在
  被抹掉。

```bash
python experiments/temporal_capacity_audit.py --self-test          # 不需要 checkpoint
python experiments/temporal_capacity_audit.py checkpoints/mobileviclip_small.pt
```

**判读方式：** 反对称占比中位数 < 0.05 **且** DC/AC 中位数 > 0.95 ⇒ 训练后的模型几乎不编码
时间方向 ⇒ 预测 RTime-Binary ≈ 50%。

⚠️ 该脚本已自测并在**合成** checkpoint 上端到端跑通，但**没有**跑过真实权重（Claude 拿不到）。
训练态 checkpoint 里时间分支是**未融合**的（`mixer_1d` / `norm_1d`）；推理态融合核是
`id_tensor + layer_scale_1d·(mixer_1d − norm_1d)`（见 `RepMixer.reparameterize`）。若默认键名
对不上，脚本会打印它找到的候选键——用 `--kernel-key` 指定，或先重参数化再存一份。

### 2b. 动态审计 —— 在锁定的 B0 权重上做纯评测扰动

用现有 eval 配置、在测试时扰动帧，**两边都跑**：MSR-VTT（外观）与 SSv2-MC（时序）：

| 扰动 | 测的是什么 |
|---|---|
| **shuffle**（8 帧随机置换） | 已部署模型的总顺序敏感性 |
| **reverse**（时间反转） | 专门测时间之箭敏感性 |
| **freeze**（中间帧重复 ×8） | *任何*多帧信息到底值多少 |
| **仅评测端 T=16** | 可能的免费增益，同时标定 1.6 的多 T 曲线 |

同时记录扰动嵌入与干净嵌入之间的**池化嵌入余弦**，分别在 stage-3 输出、stage-4 输出、池化后
三处。这能定位顺序是在**哪里**被创造或被销毁——如果 stage-4 输出已经对 shuffle 不变，那么
任何聚合器层面的修补都救不了，问题在上游。

### 2c. 每种结果各自授权什么

| 结果 | 含义 | 行动 |
|---|---|---|
| MSR-VTT **和** SSv2-MC 上 shuffle Δ ≈ 0，且静态审计显示对称低通核 | 模型顺序盲**且**整套基准看不见它 | R2 成为**唯一**值得投入的时序提案，且必须在 RTime 上测；其余时序想法全死 |
| MSR-VTT 上 shuffle Δ ≈ 0，**SSv2-MC 上 > 0** | 模型有顺序信息，问题出在**基准** | 推进 R2，加 RTime/Vinoground，按 Pareto 结果汇报 |
| MSR-VTT 上 shuffle Δ 很大 | 我们的前提错了 | 重新推导；F1 说这不可能经由读出头发生，所以它意味着 backbone 侧存在很强的顺序编码 |

**无论结果如何这都是一张论文图** —— 一条在**我们自己模型**上测出来的"逐基准可测性上界"，
而不是引用别人的，与 ROADMAP 1.6 的多 T 退化曲线放在同一格。

## 3. 三个提案

按 (期望收益 × 新颖性) ÷ (风险 + 成本) 排序，遵守第一轮 §0 的 T1/T2。

| # | 提案 | 攻击的瓶颈 | 推理开销 | 新颖性 | 结论 |
|---|---|---|---|---|---|
| **R1** | **精确冻结文本负例库** | **(d)** | **零**（仅训练期） | 作为研究低、作为工程高 | **先做——期望价值最高** |
| **R2** | **可恢复顺序的读出头**（mean → +slope → +phase） | **(c)** | ~0.1% MACs，静态 | 中高 | **做，但由 §2 闸门决定** |
| **R3** | **把 straightening 当*测量*，不当目标** | — | 零 | 中（负结果） | **做——免费图，不占实验臂** |

### R1 · 精确冻结文本负例库 —— 四份评审共同挑中的那个

**观察。** `TextTransformer.encode_text` 以**唯一一个可训练算子**结尾——
`token_emb @ self.projection_layer`（`text_encoder.py:225`）。它之前的一切都被
`freeze_text=True` 冻住（`mobileviclip_small.py:74-80`）。因此**一条字幕的投影前特征，在整个
训练过程中是一个常量。**

**为什么这很重要。** 每一篇 memory bank 的论文都把力气花在管理**陈旧性**上：编码器在漂移，
排队的特征就过期，于是需要动量编码器。而这里编码器**在结构上不可能漂移**。把投影前特征缓存
一次，每一步用**当前**投影重算，负例库就是**数学上精确的**——与文本塔此刻对这些字幕的输出
完全一致。零陈旧、无动量编码器、无队列簿记。

**为什么值得做。** SigLIP 的 batch 扫描是参照点：低于约 16k batch，对比学习质量受 batch 强烈
限制，约 32k 处饱和。**我们在全局 batch 512 —— 大约比饱和点低 30–60×。** 这是当前配置里最大
的未开采杠杆，而且与 §0 里的一切不同：它作用在**主目标**上，不在其零空间里。

同一个"冻结塔"性质还白送两样东西：

- **离线假负例屏蔽。** InternVid 的字幕会重复（"a man is talking"）。512 时假负例率可以忍，
  65k 时不能。因为文本空间是静态的，近重复掩码可以**离线一次性**预计算。它与现有的
  `caption_idx` / `get_mask(idx)` 多正例机制天然组合（`criterions.py:287`）。
- **挖掘难负例。** 预计算每条字幕在冻结文本空间里的最近邻，作为保证难的负例注入。

**不对称性——要诚实讲出来。** 这给的是**文本**负例，增强的是 v2t 方向。t2v 方向（我们的头号
指标）需要入库的**视频**嵌入，而视频嵌入**确实**会漂移，需要真正的动量队列。先做纯文本，
因为它精确且免费；只有当 t2v 落后时，再加一个规模不大的视频 FIFO。

**草图**（默认关 = 按构造逐位一致；注意是**提前 return**，不是 `+ 0*aux` —— 乘零仍会执行算子，
还可能改变 fp16 的规约顺序）：

```python
def vtc_with_bank(v, t, bank_feats=None, text_proj=None, dup_mask=None, logit_scale=100.0):
    logits = logit_scale * v @ t.t()                        # [B, B]  基线路径
    if bank_feats is not None and bank_feats.numel() > 0:
        t_bank = F.normalize(bank_feats @ text_proj, dim=-1)  # 精确：零陈旧
        extra  = logit_scale * v @ t_bank.t()               # [B, K]
        extra  = extra.masked_fill(dup_mask, float('-inf'))  # 离线预计算
        logits = torch.cat([logits, extra], dim=1)
    return F.cross_entropy(logits.float(), torch.arange(v.size(0), device=v.device))
```

**⚠️ fp16 溢出陷阱。** `temp = 1/100` 时 logit 尺度是 100，一个 `512 × 65536` 的 fp16 logit
矩阵会在负例池耗尽之前先溢出。请在 **fp32** 里算 logit 矩阵与 log-softmax，显式减最大值，
并沿负例库维度分块做矩乘。记录 `max|logit|` 与 DeepSpeed 的 skipped-step 计数。
已记入 `TROUBLESHOOTING.md`。

**非神经科学孪生（T1）。** MoCo（He 等，*CVPR* 2020）、XBM（Wang 等，*CVPR* 2020），以及
MEEL（arXiv:2103.15686）——后者已经为视频-文本检索造过跨模态 memory bank。孪生很强、也很成熟。
**未被认领的部分是那个"精确性"论证**，而神经科学的说法（互补学习系统：一个稳定的巩固存储被
回放进快速学习器，之所以成立*正因为*该存储不漂移）应当被如实标注为它本来的样子——一个对工程
事实的合理化叙述，不是推导。按 T1，**不要**把它当脑启发卖；当工程卖，把数字拿走。

**Kill 判据。** 512 → 65k 负例带来 < 0.5 R@1 ⇒ 瓶颈 (d) 诊断错误，停止投入。
**带仪表的早期检查：** 记录 softmax 质量落在库内负例 vs batch 内负例的比例（<5% ⇒ 负例库是
惰性的，砍掉这条臂）；以及正例在负例中的排名——如果多数样本面对 512 个负例时正例已经是
rank-1，那么任务在这个 batch 规模下已饱和，我们在跑扫描之前就有答案了。

**要打包进来、不要单开实验臂的：** **温度**（固定 1/100 是从 image-CLIP 继承的，偏锐；
最优值随负例数移动——把它设成可学习或直接扫）；以及 **sigmoid/SigLIP 损失** —— 它**已经实现了**
（`model["use_sigmoid_loss"]`、`vtc_loss_sigmoid`、`experiments/configs/r1a_sigmoid.py`），
带可学习 t/b 与正确的 SigLIP 初始化。sigmoid + 大负例池**就是** SigLIP 那个区制。

### R2 · 可恢复顺序的读出头 —— 瓶颈 (c) 的结构性修复

**统一三条独立建议的洞见。** 三份评审提了三种不同的读出修复；它们其实是**同一族、阶数递增**，
数值检查也确认了这点（线性斜坡与最低频相位通道相关 **0.994**）：

| 阶 | 读出 | 顺序敏感性 | 成本 |
|---|---|---|---|
| 0 | `mean`（现状） | **无**（F1） | — |
| 1 | `+ û` = 固定权重斜率 ≡ **approximate rank pooling**（F3） | 时间之箭 | ~4k MACs |
| k | `+` 相位绑定：求和前把二维平面按 `ω_j·t` 旋转 | 更细的顺序结构 | ~2k MACs |

三者都是**静态、稠密、与数据无关**的——一次 einsum 加一张常数表，再加一个 1024→512 的投影
（~0.5M MACs，约为视觉塔的 0.1%）。可直接导出到 Core ML / TFLite。这是难得的、在 T2 下
**真正免费**的机制。

```python
# Z: [B, T, C] 逐帧嵌入，由 FastViT.forward 外露（管线改动见 §5）
u0 = Z.mean(1)                                        # 现有质心
c  = torch.arange(T, dtype=Z.dtype) - (T - 1) / 2       # 对任意 T 通用（2.1 已把 T 动态化）
w  = c / (c * c).sum()                                  # T=8 时 == (t-4.5)/42
u1 = torch.einsum('t,btd->bd', w, Z)                  # 一阶项（F3）
v  = F.normalize(torch.cat([u0, gamma * u1], -1) @ W_proj, dim=-1)   # W_proj: 1024->512
```

`gamma` 是可学习标量、**初始化为 0**，`W_proj` 在 `u1` 块上零初始化，因此**第 0 步恰好等于
当前的均值池化**（C-switch 约定）。拼接前对每支做 LayerNorm——否则 `‖u1‖ ≪ ‖u0‖`，L2 归一化
之后该支贡献的角度可以忽略不计。

**决定性实验，也是本篇最好的东西。** F2 预测：**加性**位置码必须失败，**乘性**绑定必须有效。
所以跑：

```
arm-mean      : 基线
arm-additive  : 均值之前加一个学习到的逐帧加性码   ← F2 预测「没有增益」
arm-slope     : + rank-pool 斜率（F3）             ← 预测有增益
arm-phase     : + 旋转相位绑定                     ← 预测增益 ≥ arm-slope
```

如果 `arm-additive` 追平 `arm-phase`，那么 F2 是错的，上游非线性已经完成了绑定。如果
`arm-additive` 纹丝不动而其余两个动了，理论就在**我们自己的模型**上被确证。**两种结果都可发表
且都便宜**，而且它是可证伪的——多数脑启发池化论文做不到这一点。

**非神经科学孪生（T1），全部是强制基线。** (i) **Approximate rank pooling / dynamic images** ——
Bilen 等，*CVPR* 2016 / *TPAMI* 2018 —— F3 已证明它是一阶项的**精确恒等**，必须开门见山地披露；
(ii) 学习式加性位置码；(iii) **RoPE**（Su 等）——同样的旋转代数，但作用在注意力内部的
query/key 上，从未被当作**池化幸存**机制；(iv) CLIP4Clip 的 `seqTransf`，暴力版本，
在 **MSR-VTT 上值 +1.4 R@1（43.1 → 44.5）**，而 `seqLSTM` 反而**差于**均值池化 ——
**那个 +1.4 就是顺序感知聚合在 MSR-VTT 上的现实上限**，且 `seqTransf` 要付真实推理开销。
把预期校准到 MSR-VTT 上零点几个点，把分量压在 RTime 上。

相位变体的神经科学依据：theta-gamma 相位编码（O'Keefe & Recce，*Hippocampus* 1993；
Lisman & Jensen，*Neuron* 2013 —— 相继的项占据相继的 gamma 周期，所以*顺序即相位*；
Lisman & Idiart，*Science* 1995 推出 7±2 的容量，接近我们的 T=8）；时间上下文漂移
（Howard & Kahana，*J. Math. Psych.* 2002）；非线性混合选择性作为变量可解码的原因
（Rigotti 等，*Nature* 2013）。形式化的祖先是全息约简表示（Plate，*IEEE TNN* 1995）。

**Kill 判据。** RTime-Binary 停在 50.0% ⇒ 读出不携带任何顺序信息 ⇒ 前提错误。次级判据：
评测时把 `gamma → 0` 做消融，若 R@k 不变则该支是装饰品。另外，若 MSR-VTT 退化超过
**预注册**的不退化余量也砍——那个余量必须在看到数字**之前**定好。

### R3 · 把 straightening 当测量，而不是目标

第一轮的直觉——也是显而易见的脑启发动作——是加一个感知拉直损失
（Hénaff, Goris & Simoncelli，*Nat. Neurosci.* 2019；Hénaff 等，*Nat. Commun.* 12:5982, 2021）。
**三条独立的理由说：不要把它做成目标：**

1. **F4** —— 它活在检索梯度的零空间里，而它的全局最优（残差塌缩）是免费的。
2. **先验工作占了约 85%。** 拉直作为训练目标：Niu, Savin & Simoncelli（*NeurIPS* 2024）。
   视频里的拉直、且明确引用 Hénaff：**LiFT / "Chirality in Action"**
   （Bagad & Zisserman，*NeurIPS* 2025）。而非神经科学孪生来自 **2016** ——
   Jayaraman & Grauman 的 "Slow and Steady Feature Analysis" 惩罚二阶时间导数，那就是
   去掉神经科学的拉直；曲率损失只差在尺度不变。
3. **它与我们的读出头相消。** 对理想直线轨迹 `z_t = z_s + (t/T)z_d`，均值是**中点**
   `z_s + z_d/2`，而这个中点对倒放视频**完全相同**。如果目标是时序能力，先把轨迹拉直再平均
   是自我拆台。LiFT 之所以有效，只因为它把 `z_d` 保留为一个独立的**带符号**动态 token ——
   这恰恰就是 R2 的一阶项所恢复的东西。

**该做什么——免费，而且是真结果。** 在基线上**测量**轨迹曲率，并在训练过程中记录它。
已有报道称拉直会在鲁棒网络中**自发涌现**（Toosi & Issa，2023），并不需要被要求。
曲率度量（Hénaff 约定）：

```python
d = Z[1:] - Z[:-1]; d = d / (norm(d, axis=-1, keepdims=True) + 1e-8)
curvature = degrees(arccos(clip((d[:-1]*d[1:]).sum(-1), -1, 1))).mean()
```

报告 clip 上的**分布**，并且永远对照三个零假设：**帧打乱**（主要——到底有没有任何时序结构？）、
**像素域**（Hénaff 的分母；报告相对曲率 `c_model − c_pixel`）、**未训练 backbone**。
在原始嵌入上计算——**绝不要**在 PCA/平滑后的坐标上算，因为随机游走的低维投影可以看起来像一条
优美的曲线。曲率**不能跨采样率比较**，所以所有实验臂固定同样的 T 与步长。

**很可能的头条结论，而且值得拥有：** 在 T=8、约 1 fps 下，我们的 8 个点很可能是围绕语义质心的
一次紧凑随机游走，而不是一条光滑曲线——那样的话曲率就坐在打乱零假设的值上（~90°），
**根本没有轨迹可拉直**。一条曲率与 R@k 之间干净的平坦剂量-反应曲线，是针对一个当前学界视为
不言自明地好的假设的**可引用负结果**，而且零 A/B 成本。

## 4. 本轮被杀掉的想法及理由

| 想法 | 为何被杀 |
|---|---|
| **把 straightening / slowness / 时序去相关做成*损失*** | F4（零空间 + 免费塌缩）；先验工作已占；与均值池化相消。只保留**方差地板**项（`relu(γ − std_t)`）作为可复用的塌缩护栏 |
| **潜空间下一步预测（V-JEPA 作辅助）** | F4；在恒等预测器下塌缩使损失恰好为 0；需要 stop-grad **且** EMA **且** 预测器不对称 **且** 方差地板——给一个没有机制的项配四道护栏；这个格子在 2026 的文献里正在快速关闭 |
| **事件分割池化** | **T=8 没有空间** —— 7 个间隔、每段 2–4 帧，而在约 1 fps 下每个间隔都可以算作边界。还引入动态控制流（违反 T2）。只有当长视频基准上 T ≥ 32 时再回看 |
| **由粗到细 / 时间模糊课程** | 孪生就是随机 T∈{2,4,8,16}，而 C2 已经在做；课程需要调度空间，而我们只有**从预训练初始化出发的 3 个 epoch**；FluxViT（*ICCV* 2025）占了分辨率课程这条道。还有一个设计陷阱：有序课程必须匹配 `E[T]` 与完整边缘分布，否则它量的是"帧多=算力多" |
| **时序顺序 / 打乱 / 时间之箭预测头** | 已被掩码视频建模取代；它逼帧去编码相位，而 F1 说均值会丢掉相位；它与 VTC 目标对抗，而 VTC 本身据报会**侵蚀**时间方向 |
| **跨 T 的时序去相关** | 按此提法在统计上不可能：从 **T=8 个样本**估计 512×512 协方差，秩 ≤7 |
| **任何新的 token 合并 / 剪枝 / 选择** | 这条道在 18 个月内已关闭：TempMe（*ICLR* 2025）、ResidualViT（*ICCV* 2025）、EVS、FluxViT |
| **帧差分输入前端** | 稠密卷积的开销与输入能量无关，因此它无法攻击 (a) —— 而攻击 (a) 是它唯一的存在理由。一条值得记录的一般结论：**没有任何无教师、只在训练期起作用的想法能攻击 (a)**；(a) 需要推理期改动 |

**两个被降级而非杀掉的**（可以做，但别当脑启发贡献）：面向瓶颈 (b) 的
**分解式/分离式时空注意力** —— 把注意力显存从 512² 降到 64×8²，静态且对导出友好，很可能是
正确的修法，但那是 TimeSformer / axial / Video-Swin，神经科学没有添加任何东西；以及
**小的可训练文本适配器**（在最后几个文本块上 LoRA r=8–16；注意配置 schema 里
`open_text_lora` 已存在）—— 因为 LiT 限制了两个空间能对齐到什么程度，它很可能是高杠杆的，
但它改变了既定的 LiT 设计，因此是比加一个损失项更大的决定。

## 5. 工程前置条件（已对代码核验）

**P1 —— 把逐帧轨迹外露。** `FastViT.forward` 在 `mobileviclip_small.py:1377` 造出 `[T,B,C]`，
却在 `:1384` 只返回池化后的 `[B,C]`；损失活在上一层的 `MobileViCLIP_Small.forward`
（`:126-155`），根本看不到它。**每一个**轨迹类提案（R2 的读出、R3 的曲率记录、任何残差诊断）
都需要这一次性的管线改动。它是共享基础设施：付一次，下一个想法的边际成本接近零。
默认路径保持逐位一致（只有在请求时才返回额外张量）。

**P2 —— `loss_weight` 陷阱（影响已合入的方案）。** `tasks_clip/pretrain.py` 做的是
`loss = sum(loss_dict.values())`，而 `criterion.loss_weight` **只**被用来构造日志计量器
（`loss_names = [... if v != 0]`，`:48`）。**配置里的权重从未被乘进损失。** 新的辅助项必须在
自己的 `forward` 里施加权重（读 `self.config.criterion.loss_weight`），否则在配置里设
`kd_geo=0.5` 只会悄悄改变日志输出、而不改变任何优化行为。**这条适用于已经合入的 B1 几何蒸馏
方案。**

**P3 —— 损失平衡，适用于我们真要跑的任何辅助项。** 用第 0 步的**梯度范数匹配**来定 λ
（`λ = ρ·‖g_main‖/‖g_aux‖`，`ρ ∈ [0.05, 0.1]`），而不要猜——猜出来的常数无法从 10k 试点迁移到
10M，这正是试点误导人的常见方式。把 λ 在前 5–10% 的步数里从 0 爬坡，且**起点要在 LR warmup
之后**（两个同时在动的调度会产生无法归因的不稳定）。当心 `different_lr` 的交互：一个 1e-3 的
新头对上 1e-5 的 backbone 是 **100× 比值**；前约 500 步从头到干路做 stop-gradient。

**P4 —— 能省下全量实验臂的试点诊断。** 10k 试点无法给方法排序，但它**能**证明一个想法在机制上
不可能有帮助。在最后一个共享块上记录**辅助损失与主损失的梯度余弦**：持续 `cos ≈ 0` 就是 F4
的经验确认（该项在零空间里）⇒ **在花掉一次 H100 之前砍掉这条臂**。`cos < 0` ⇒ 直接冲突。
`cos ∈ [0.05, 0.3]` ⇒ 唯一值得开全量臂的结果。同时记录 `‖g_aux‖/‖g_main‖`
（超出 [0.01, 0.3] ⇒ λ 标定错了），以及那个架构特有的塌缩征兆：**逐通道时间核 DC/AC 比**
趋向 1。

## 6. 对第一轮的更正

1. **A1（惊奇池化）比第一轮声称的更弱。** 它能在 F4 下幸存（重加权改变了池化均值，因此对损失
   可见）—— 但 F1/F2 表明：**任何**加权方案，包括它必须打败的注意力池化，仍然是**顺序盲**的：
   重加权一个集合并不给它排序。A1 只能利用**外观**显著性（压低模糊或无信息的帧），
   永远拿不到时序顺序。第一轮把它包装成预测编码故事里的聚合器修复；它不是。R2 才是顺序修复。
2. **N4 / A2（分级时间窗）不受 F4 影响**（它改变特征、因而改变均值），但受 §1 的可测性上界封顶
   —— 它在 SSv2-MC 上的预期收益应当对照审计结果重读，而不是假定成立。
3. **B1（几何蒸馏）继承 P2 的 loss-weight 陷阱** —— 它的配置草图写了
   `criterion["loss_weight"].update(dict(kd_cos=1.0, kd_geo=1.0))`，按 P2 这对优化毫无作用。
   实现时修掉。
4. **第一轮"剖析逐帧 vs stage-4 的 MAC 占比"这一前置条件仍然成立**，现在再加上 §2 的审计，
   构成第二道零成本闸门。
