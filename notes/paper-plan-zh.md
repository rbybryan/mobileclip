# 顶会论文计划(v1)—— 改进路线图的重新裁剪(中文版)

**日期:** 2026-07-16
**对应英文版:** `notes/paper-plan.md`
**目标转变:** 此前的笔记(`model-architecture-improvements{,-zh}.md`、
`script-level-optimizations-zh.md`)是一份*复现 + 改进的待办清单*——
10 条模型提案 + 13 条脚本修补,抽象地看每条都值得做。本文按一个不同的目标
重新裁剪这份清单:**做出一篇有新意的顶会论文**(主目标 CVPR 2027,
截稿约 2026 年 11 月;冲刺备选 ICLR 2027 约 9 月截稿;ECCV'26 窗口已关闭)。

因此下文把所有条目分成三类:**主线 / 组件 / 砍掉**。

## 一、故事(一句话)

> **数据强化(Dataset Reinforcement)训练 + 时间维弹性蒸馏,让一个移动端
> 视频 CLIP 用单一模型在任意帧数预算 T ∈ {2…16} 下逼近大得多的视频-文本
> 模型——且推理零额外开销。**

工作标题方向:*"Video Dataset Reinforcement: Training Elastic Mobile
Video-Text Models"*(名字待定)。

为什么选这条主线而不是其他候选:

- **新颖性站得住。** MobileCLIP/MobileCLIP2 的 DR 配方**没有任何已发表的
  视频版对应工作**(2026-07 文献扫描核实)。但单纯"把 DR 搬到视频"有被评
  *增量式(incremental)*的风险——所以主线加入一条真正新的轴:
  **时间维弹性蒸馏**(教师离线只编码一次 T=16 帧;学生训练时随机
  T ∈ {2,4,8,16},对齐*同一份*存储的教师 embedding)。由此得到一个
  帧数即部署旋钮的单一 checkpoint,而"从 16 帧教师蒸馏出的 4 帧移动端
  模型打败 8 帧 VTC-only 模型"是一条全新的、可检验的结论。
  没有任何已有工作把 DR 式离线强化与帧数弹性结合起来。
- **这是我们验证过的所有条目里期望收益最高的一项**(图像侧 DR 在同等
  学生规模下值 +2–5 个点;P5 原本就被排为"预期精度收益最大")。
- **匹配我们实际拥有的算力**(8×V100-32GB):贵的部分只是一次离线教师
  推理(尴尬并行、可断点续跑),而学生训练反而*比基线更便宜*
  (教师代劳了难例挖掘;MobileCLIP 报告所需步数更少)。
- **全部复用已验证的仓库资产**:`caption_augmentation` 钩子、
  `vtc_loss_sigmoid`、`AttentionPoolingBlock` 模式、`interpolate_pos_embed`。

## 二、审稿人视角的贡献列表

| # | 贡献 | 来源 | 新颖性层级 |
|---|------|------|-----------|
| C1 | **视频数据强化(Video DR)**:InternVideo2 教师离线过一遍 InternVid-10M-FLT,存储视频+文本 embedding(真实字幕 + 重字幕合成字幕);学生用 VTC + embedding 蒸馏 + 相似度矩阵蒸馏训练 | P5 + `data-quality-caprl-scheme.md` | 视频侧首创;配方级 |
| C2 | **时间维弹性蒸馏**:时序算子 T 无关化 + 随机 T 训练、对齐固定的 16 帧教师目标 → 单一模型、帧数即旋钮;Pareto 曲线在每个预算点均胜过固定 T 基线 | P2 **并入** P5 | 全新想法——正是它让这成为一篇论文而非一次移植 |
| C3 | **配方组件 + 消融**:sigmoid 多正例损失(可学习 t/b,移植 `get_mask`)、时间维注意力池化头(零初始化,严格不退化) | P4 + P3 | 已知技术,我们出消融表 |
| C4 | **结果**:多帧数下的零样本检索(MSR-VTT/DiDeMo/ANet/MSVD/LSMDC)+ 零样本分类(K400、SSv2-MC)、**端侧延迟表**,对比 MobileViCLIP / InternVideo2-S/B / TempMe 类高效基线 | 评测框架 | — |

折入 C1 损失循环的免费彩蛋:套娃前缀(P10)——一段话 + 一列表格,
零额外训练。

**新颖性抗辩(预判最显然的审稿意见):**"这不就是视频版 MobileCLIP2 吗?"
——不是,因为视频以几种具体方式打破了图像配方,而我们逐一解决:
(a) 教师的帧数 ≠ 学生的帧数(C2 是答案,且是新的);
(b) InternVid 字幕噪声大、且*同一视频的多个 clip 共享字幕*——batch softmax
会把它们当成假负例;带 `idx` 掩码的 sigmoid 多正例目标(C3)是视频侧特有
的修法;(c) 逐帧取平均丢掉了教师 embedding 里蕴含的时序显著性——注意力
池化(C3)正是蒸馏出的时序信号获得容量的地方。(a)–(c) 各占一行消融。

## 三、既有条目逐一处置

### 主线(按此顺序做)

| 旧编号 | 新角色 | 相对旧计划的变化 |
|--------|--------|------------------|
| P5 | **C1 核心** | 升级:合成字幕通道从第一天就加入(CapRL 笔记);教师 = InternVideo2-L @ T=16(先在 10 万条切片上实测再定 L 还是 1B) |
| P2 | **C2 核心** | 升级,不再是孤立的"解除 T=8 硬编码"杂活:T 无关 reshape + `temporal_embedding` 插值现在是*方法本身的一部分*,随机 T 训练即贡献点 |
| P4 | C3 组件 | 不变(接通 `vtc_loss_sigmoid` + 移植 `get_mask`,SigLIP 初始化 t=log 10、b=−10) |
| P3 | C3 组件 | 不变(零初始化注意力池化,作用于 T 个帧 embedding) |
| P10 | C1 彩蛋 | 简化:只保留嵌套前缀损失循环,不做独立研究 |

### 简化(只做解锁主线所需的最小版本)

| 旧编号 | 最小版本 | 放弃的部分 |
|--------|----------|-----------|
| P1 | 环境升到 torch ≥2.0 + SDPA(若 DeepSpeed 卡住则 1.13 上用 xformers)。纯基础设施,论文实现细节里一句话 | 任何"高效注意力"的论文主张 |
| P9 | 仅当延迟表需要时:用 C1 损失微调一个分离式注意力的*部署变体*,报告为一行消融 + Core ML 导出 demo | 分离 vs 联合的完整研究;混合变体 |
| H1/H4 + 冻结 bug | **任何基线数字之前的强制卫生项**:移除 `set_detect_anomaly`、清除 spikingjelly、修复 `hasattr(name,'_1d')` | — |
| H3 | 强制项:`dsl/` 与 `raw/` 两个口径分开报告,并在**第一个 A/B 之前**把论文口径钉死为其一 | — |
| H5 | 可选但便宜:评测按 rank 分片——在下文约 15 个 A/B 里能收回成本 | — |

### 砍掉(从本项目移除;笔记留作日后)

| 旧编号 | 砍掉理由 |
|--------|----------|
| P6(时序 token 合并) | TempMe 已发表(ICLR'25),作为我们的贡献属于衍生工作;且我们自己的分析显示第 4 阶段注意力只占 ~8% MACs。**改为引用并与之对比**——TempMe 变成基线表的一行,不是工作项 |
| P7(非对称帧编码) | 真有新意,但风险抵得上*第二篇论文*;C2 已经用低得多的风险占住了"更少帧、同等精度"的地盘。若 C2 落地,作为后续工作重启(C1 的自蒸馏损失恰是 P7 需要的) |
| P8(mct 文本塔) | 纯压缩、无新意,与故事不交互。最多放未来工作 / 附录 |
| H2、M1–M3、L1–L5 | 零论文价值的工程打磨;仅当某个具体训练被显存/速度卡住时才做 |
| whitespace §3(量化)、§4(帧选择) | §4 被 C2 吸收(弹性 T 是帧选择的更强版本);§3 继续搁置 |

whitespace §2(时序难负例)被**吸收**:每条 clip 的教师 embedding 存好后,
时序难负例(打乱帧序的 clip 由教师打分)几乎免费——作为 C1 内部的
*冲刺消融*保留,不再是独立阶段。

## 四、实验计划(8×V100,所有 A/B 均等步数、等数据预算)

```
第 1 周    卫生闸门:H1、H4、冻结 bug、H3 口径钉死、torch 升级(P1)。
           重跑基线评测 → 锁定基线数字(两个打分口径都存档)。
第 2 周    C3 A/B(便宜的 3-epoch 短训):sigmoid 损失;注意力池化;二者叠加。
           淘汰标准:组件相对锁定基线 ≥ +0.3 R-Sum 才保留。
第 2-3 周  教师推理,分阶段:10 万条切片 → 实测 GPU 时数、存储、以及
           *教师在我们评测集上的零样本质量*(合理性检查:教师必须大幅
           压过学生)。据此定 InternVideo2-L 还是 1B。然后全量 1000 万
           (可续跑分片;约 1 GPU-周量级——与第 3 周的代码并行推进)。
第 3 周    C2 代码:T 无关算子 + temporal_embedding 插值 + 随机 T 采样器。
           单元测试:T=8 路径与旧硬编码路径逐位一致。
第 4-6 周  主实验(论文表 1):
             R0 基线 VTC-only,固定 T=8              (复现)
             R1 + C3 组件                            (第 2 周的最优组合)
             R2 + C1 DR 损失(固定 T=8)             → 单独隔离 DR 增益
             R3 + C2 随机 T(完整方法)              → 头条模型
           每个约 3 epoch @ InternVid-10M ≈ 原论文训练预算。
第 7 周    消融:λ1/λ2、字幕配比、T 分布;MRL 列;
           (冲刺)时序难负例;(如需)P9 部署变体。
第 8 周    端侧延迟(Core ML / ONNX,T ∈ {2,4,8,16})、TempMe 与
           InternVideo2-S/B 基线表、写作。
缓冲       距 CVPR 截稿约 6 周,用于重跑与 rebuttal 加固。
```

**Go/no-go 闸门:**

- R2 之后:DR 增益 < +1.0 平均 R@1(相对 R1)→ 主线告急;后备方案 =
  论文转向效率故事(把 P7 + P9 升为主线,DR 降为训练细节)。
  *到那时*再决定,不提前。
- R3 之后:弹性模型在 T=4 下必须打败"固定 T=4 训练"的基线,且与自身
  T=8 模式差距 ~1 个点以内——否则 C2 沦为"我们也试了",论文靠 C1+C3
  出货(更弱但可行,TMLR/AAAI 档)。

## 五、相对旧排期的变化,一眼看完

- 旧的阶段 0–3 把 P1–P10 当平行赛道;**现在只有一条主线**(C1→C2)
  外加便宜的组件 A/B;效率线(P6/P7/P9)被砍掉或压缩为基线/一行消融。
- P2 原是"工程前置";现在是**新颖性的一半**(C2)。
- P5 的合成字幕从"可选通道"提前到第一天(它是 MobileCLIP2 最大的单项
  杠杆,也是我们对字幕噪声的防线)。
- 脚本清单:只有 4 个正确性条目(H1、H3、H4、冻结 bug)作为阻塞项
  存活;其余全部机会主义处理。
