# MobileViCLIP 架构创新 · 第三轮(性能 × 效率双目标)

**日期:** 2026-07-28
**性质:** 在 [`model-architecture-improvements-zh.md`](model-architecture-improvements-zh.md)(P1–P10)
之外的**新增架构方向**,由两位独立专家(视频-VLM、高效深度学习)分别起草后合并去重。
每条都同时盯两个目标:**检索性能**与**端侧效率**(FLOPs / 峰值激活显存 / Core ML 可导出性)。

**两条约束是选点的根本依据(源码已核实,见 P1–P10 那份 §一):**
1. **逐帧卷积(×8 帧)主导总 FLOPs**(≈55G)—— 任何不在 *卷积阶段* 减少时序 token 数的做法都动不了这 55G;
2. **第 4 阶段联合 T·H·W softmax 注意力是峰值显存 + Core ML 导出瓶颈**(仅占 ~8% MACs,却主导峰值激活,且现有唯一导出脚本静默跳过全部时序算子)。
   时序混合本身是**可重参数化**的(RepMixer 的并联 Conv1d 推理期折叠成单卷积)——这是最大的可利用杠杆。

> ⚠️ 现状提醒:本文件所有条目都是**架构方向,尚未做等步 A/B**。V100 上只做过 10k 链路冒烟,
> 没有任何改进被证明有效;真值压在 b100/H100 全量实验上。落地任一条前,先补对照实验。

以下按"是否利用我们的具体结构 × 双轴影响 × 两位专家是否收敛"排序。**收敛项(两位独立提出)置顶。**

## 第一梯队 —— 高杠杆、直击结构瓶颈(两位专家均强推)

### C1. 把 stage-4 联合注意力**蒸馏进**可重参数化时序卷积分支 → 推理期彻底无注意力
*(两位收敛:VLM#1 + DL#6)*
- **机制:** 联合 T·H·W 注意力只留作**训练期教师**;stage-4 增设若干可重参数化 Conv1d + 小 pointwise-mixing 分支,用特征匹配 / attention-transfer 损失让卷积**吸收**其时序混合;推理期把这些分支 fuse 成单卷积(就是你已在用的 RepMixer 技巧),**删掉注意力算子本身**。
- **为何对我们:** 导出脚本本来就静默丢弃所有时序算子——这让"丢弃"从**有损**变成**有原则**。512×512 注意力矩阵是峰值显存 + 朴素 softmax 成本大头;删掉它峰值显存塌缩、最难导出的算子消失,而时序能力活在工具链本就能导出的卷积里。**严格超越 P9"分离式时空注意力"**(那个推理期仍保留 live 的空间 softmax)。
- **成本/风险/导出:** 推理图纯 conv+pool,Core ML 完全可导出。风险:线性卷积无法完美复现内容相关注意力,时序难样本可能掉 0.5–1.5 R@1。对冲:保留单个廉价全局时序 summary token(见 C4)。训练成本适中(一条损失 + 分支)。
- **锚点:** FastViT/MobileOne/RepViT 重参数化;attention→conv 蒸馏。**两位都列为最高价值一步。**

### C2. 早期时序收缩(X3D/MoViNet 式金字塔池化调度)
*(两位收敛:DL#2 + VLM#2)*
- **机制:** 不让全 8 帧穿过全部四阶段。高分辨率早期阶段跑全 8 帧,随空间下采样 / 通道变宽**逐级时序池化 8→4→2**(strided 时序 conv 或 avg-pool),让最贵的深层阶段(含 stage-4 注意力)只见少数帧。
- **为何对我们:** 55G 由"逐帧卷积×8"主导,深层通道最宽、MACs 最集中,在那里砍半帧数 ≈ 直接乘法级减 FLOPs,且不动输入分辨率 / 检索相关空间细节;还顺带减少 stage-4 token 数,减轻 C1 与峰值显存。**唯一同时打中两个主导成本的点。**
- **成本/风险/导出:** strided 时序 conv/pool 可导出。风险:过早池化冲淡短时动作线索——需在 MSR-VTT/DiDeMo 动作敏感切片上消融池化深度。与 C1 干净耦合。
- **锚点:** X3D(CVPR'20)、MoViNet(CVPR'21)。

### C3. 因果时序卷积 + 流式缓冲(O(1) 流式显存,顺带天然弹性 T)
*(两位收敛:DL#4 + VLM#3)*
- **机制:** 非因果时序算子换成**因果** Conv1d,缓存每层 k−1 帧激活的小环形 buffer;逐帧更新,保留时序感受野而不一次物化全 T 帧激活。推理从"8 帧批推"变成真正逐帧流式。
- **为何对我们:** 峰值激活显存变成**与 T 无关的常数**(而非联合注意力的 O((THW)²)),并从结构上消解硬编码 T(不是把常数改成变量而已,是 P2 的更强形态)。
- **成本/风险/导出:** buffer 可作 stateful Core ML(支持)或展开成固定窗口图。风险:因果只用过去帧,时序上下文弱于双向,对"一个 summary embedding"可接受,和 C1 搭配好。中等工程量。**MoViNet stream buffer 是端侧可导出的直接证据。**
- **锚点:** MoViNet stream buffers(CVPR'21);TSM 零 FLOP channel shift(ICCV'19)作更廉价的纯 slice+concat 时序原语。

## 第二梯队 —— 稳、低风险、near-free

### C4. 时序 register / 潜变量瓶颈注意力(若仍保留任何注意力)*(VLM#4)*
- **机制:** 用 R≈8–16 个**学习的时序 register token** 对 512 个时空 token 做 cross-attention(Perceiver 式潜变量瓶颈),再广播 / 池化回来。
- **为何对我们:** O((THW)²)=512² → O(THW·R)=512×16,约 **30× 缩小**主导峰值显存的注意力矩阵,仍是**标准 softmax**、Core ML 可正常导出。是 C1 线性重参数化掉点太多时的**优雅退化后备**。区别于 P6 TempMe(按相似度合并 vs 学习潜 query)。
- **锚点:** "ViT Need Registers"(ICLR'24)、Perceiver、vid-TLDR(CVPR'24)。

### C5. 时序多分支过参数化块,推理期折叠回单个 Conv1d *(DL#1)* —— **建议最先做**
- **机制:** 把现有时序 DW-Conv1d(k=3) 训练期泛化成线性集成:并联 k=3、k=5、dilated-k=3(等效 k=5–7)、identity,各带 BN + 可学 scale;因全线性+BN,推理期代数折叠成**单个最大核** DW-Conv1d。
- **为何对我们:** 最干净的"免费午餐"——**推理成本 +0**(k=7 DW-Conv1d 过 512 token 相对 55G 可忽略),只增训练期时序感受野与优化多样性。只涨性能、不付效率代价,正是重参数化的意义。风险最低。
- **锚点:** UniRepLKNet(CVPR'24)、RepViT(CVPR'24)。

### C6. 可学温度 + 冻结文本塔的 LoRA/bias 微调(导出期 merge,零推理成本)*(VLM#7)*
- **机制:** 丢掉写死的 1/100 温度改**可学**;给冻结文本塔加 rank-8 **LoRA**(或仅 bias),联合训练、**导出期 merge 进权重**(推理零成本)。
- **为何对我们:** 硬写死温度 + 全冻结 LiT 文本塔留了易得的校准 / 对齐精度在桌上。LoRA 让文本几何略微贴合视频分布而推理零成本;可学 scale 本是 CLIP 标配却当前缺失。**区别于 P8"文本塔瘦身"——这是廉价解冻,不是缩小。**与 SigLIP 损失(P4)叠加 = 复利型 near-free 提升。
- **锚点:** LoRA(2021)、SigLIP/SigLIP2 可学 bias/温度。

### C7. 廉价 RGB-diff 运动 side-token,池化前融合 *(DL also-ran + VLM#5,两位都保守)*
- **机制:** 帧差(t+1 − t)过一个极小共享分支产出少量"运动 token",与外观 token 拼接后再做视频池化,给运动盲的 mean-over-frames 头补时序信号。
- **成本/风险/导出:** 低成本、Core ML 干净(减法+conv)。**两位都提醒:InternVid 检索偏外观主导,预期增益零点几个点** —— 当廉价 add-on,不是头条。除非评测集运动重。
- **锚点:** TSN RGB-Diff、SlowFast。

### C8. 低秩双线性时序池化头 *(VLM#6)*
- **机制:** 用低秩二阶(compact bilinear / 跨帧协方差)池化替代 mean,捕捉跨帧共现统计,投影回 embedding 维。
- **成本/风险:** 可导出(matmul+proj),比加注意力便宜。**作为注意力池化(R1b)的替代而非叠加**;对已调好的注意力池化增益可能边际,须保持低秩以防维度爆炸。
- **锚点:** Compact bilinear pooling(2016)复兴。

## 横切前提 —— 量化感知(做 C1/C5 前必读)

### C9. 重参数化-感知的 INT8 重设计 *(DL#5,关键警告)*
- 因为本轮 C1/C5(及现有架构)都**重度依赖重参数化**,而重参数化折叠出的 fused kernel **动态范围极大,是 INT8 已知地雷**——正是让 RepVGG/FastViT 变快的 branch-folding,会产生在 naive PTQ 下崩溃的权重。**增益会在 NPU 上静默蒸发。**
- 做法:按 QARepVGG 式拓扑约束 branch scale、去掉 fusion 后 BN,使折叠权重落在紧 INT8 范围;用 **QAT 而非 PTQ**。这是"让效率在硬件上真实存在"的前提,不是可选项。
- **锚点:** QARepVGG(2022)。

## 明确的死路(两位独立判定一致 —— 强信号,别在端侧浪费精力)

- **Delta / skip-convolution 稀疏冗余计算**(只对关键帧全算、其余帧只更新变化区域):理论上正是冲着"逐帧卷积主导"去的最诱人攻击,但需要**动态输入相关稀疏**(gather/scatter + 数据相关 mask),**Core ML / TFLite 静态图导出器处理不了或极差**,常见理论减 FLOPs 却 wall-clock 更慢、导出崩,还与量化打架。**两位都判死路** —— 只适合服务器端"fast"变体,不投端侧。锚点:Skip-Convolutions(CVPR'21)、Eventful Transformers(ICCV'23)。
- **Mamba / SSM 时序混合器**替换 stage-4:纸面 O(N) 诱人,但 **selective-scan 是 Core ML 自定义核噩梦**、端侧不成熟。**两位都说部署就跳过。** 要线性注意力宁可用 plain linear / agent attention(ECCV'24);C3 的因果流式卷积能拿到 ~80% 流式收益且无导出痛。
- **文本条件化的视频池化:** 检索协议下 gallery 视频 embedding 是**无 query 预计算**的,视频侧任何文本条件化都破坏协议 —— 排除。
- **CoCa 式 caption 解码头:** 增自回归解码成本、与冻结文本塔冲突,端侧不值。

## 建议排序(两位专家一致的下注)

```
先手(免费/前提):  C5(过参数化时序块,推理+0)+ C9(量化前把 INT8 地雷拆了)
主攻(打两约束):  C1(注意力→卷积蒸馏,杀导出瓶颈)+ C2(早期时序收缩,砍 55G FLOPs)
near-free 加成:   C6(可学温度 + 文本塔 LoRA,导出期 merge)—— 与 P4 SigLIP 叠加
后备/独立线:      C4(register 瓶颈注意力,C1 掉点时的优雅退化)
                  C3(因果流式卷积,作独立的端侧流式部署模式)
低优先 add-on:    C7 / C8(视评测集是否运动重再定)
```

- **一句话下注:C1 + C2** 同时攻克两个绑定约束(导出/峰值显存 + FLOPs),且都复用你已有的机器;**C5** 免费垫底、**C6** near-free 顺手存;**C4** 留作 C1 的退化后备。
- 所有 A/B 沿用 P1–P10 那份的纪律:**等步数、等数据预算**,评测 MSR-VTT / DiDeMo / ANet 零样本检索 + K400 零样本分类,时序敏感项(C1/C2/C3/C7)加测 SSv2-MC。
- 与既有清单的关系:C1 强化并超越 P9;C3 是 P2 的结构化强形态;C5 是 P3/时序分支的重参数化增强;C6 与 P4/P8 互补(解冻 ≠ 瘦身);C4 是 P6 的另一条路(潜 query vs 相似度合并)。
