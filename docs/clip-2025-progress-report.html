§ 01

执行摘要:五条主线

2025 年,CLIP 家族已从"单纯的对比学习编码器"演变为多目标训练的通用视觉骨干。五条趋势同时推进。

Backbone

编码器沦为 VLM 骨干

研究重心从"训练编码器"转向"被大模型冻结复用"。零样本 ImageNet 退居次位,下游 VQA / OCR 才是主战场。SigLIP 2 已是 2025 事实上的默认多模态骨干(Qwen3-VL、Gemma 3)。

Saturation

零样本 ImageNet 饱和

开源前沿卡在 ~85%;CoCa 于 2022 创下的 86.3%(闭源)至今未被零样本超越。年增益从 +10 分掉到不足 1 分。

Multilingual

世界级数据,无"英语税"

MetaCLIP 2 证明:从零在 300+ 语言全球数据上训练,反而提升英语零样本(81.3% > 80.5%),打破"多语言诅咒"。

Objective

训练目标"大杂烩化"

对比损失叠加字幕生成、自蒸馏、掩码预测;更激进者(AIMv2、OpenVision 2)彻底弃对比,只用自回归/字幕生成。

On-device

蒸馏即数据 · 端侧爆发

Apple 把教师嵌入+合成字幕离线烘焙进数据集;DeepMind 证明"主动筛选=隐式蒸馏"。~30–300M 小模型已能在手机上跑到 77–82% 零样本 ImageNet。

§ 02

核心论点:端侧正在逼近前沿

在一部 2020 年的手机(iPhone 12 Pro Max)上,MobileCLIP2 用 ≤27 ms 的图+文编码延迟,把零样本 ImageNet 推到 81.9% —— 距离需要 1–2B/18B 参数或服务器 GPU 才能达到的 ~85% 开源前沿,仅差约 3 分。

一句话:「多模态强化训练」把一个大 CLIP 集成的知识离线蒸馏进小学生模型,让精度/延迟帕累托曲线大幅平移 —— 这正是本仓库(MobileCLIP)路线在 2025 年被验证成功的核心。

深挖 A · 训练配方MobileCLIP2 的 DFNDR 数据强化配方

MobileCLIP2 的精度红利几乎全部来自数据侧的离线蒸馏,而非架构 —— 核心是把 v1 的 DataCompDR 换成更强的 DFNDR(DFN 数据强化)。所谓"强化",是把教师模型的嵌入与合成字幕离线预算、烘焙进数据集,训练时当作廉价的知识蒸馏回放。

论文点名的三个关键杠杆:
· 教师集成配对(logit scale 70.0 + 60.0)带来 +2.8% ImageNet(相对最佳单教师);
· 对比蒸馏中的温度调优被强调为核心可调项;
· 字幕器微调(MSCOCO-38k 默认,DOCCI 略优 +0.8%)提升字幕多样性,且多模型字幕组合是可加的。
净效果:MobileCLIP2-B 在架构与延迟不变下,比 v1-B +2.2 分(76.8 → 79.4)。

深挖 B · 效率之争ACED ⟷ MobileCLIP:两种蒸馏哲学

同样是"把大 CLIP 塞进小模型",Apple 与 Google DeepMind 走了相反的路 —— 一个离线显式存嵌入,一个在线隐式靠数据筛选。

维度MobileCLIP · 离线 / 显式ACED · 在线 / 隐式
机制预算教师嵌入 + 合成字幕,烘焙进数据集,训练时廉价回放按"可学习性"对整批在线选样,对齐大型冻结参考模型
核心主张存一次,训练极省;可复现"主动筛选 = 隐式蒸馏",无需额外损失项即胜过显式 KD

代表结果MobileCLIP2-S4 81.9%(端侧)ACED-F0 68.5% @3.3 GFLOPs;F1 74.9;F2 76.9
裁决?尚无定论。ACED 自报在 27 任务均值上以更低 FLOP 超过 MobileCLIP-S0/S1/S2(注意:是 27 任务均值,非 ImageNet 单项)。两条路线也并非对立 —— ACED 本身 = 主动筛选(ACID)+ 轻量显式 KD,JEST 是其前身。选择取决于瓶颈:存储/可复现优先 → 离线(MobileCLIP 路线);存储受限、愿付在线算力 → 在线(ACED 路线)。对本仓库(MobileViCLIP 复现)而言,MobileCLIP 的离线强化数据是现成、可复现的起点。

§ 06 · 深度对比

端侧视频 CLIP:MobileViCLIP

MobileViCLIP(ICCV 2025,arXiv 2508.07312,南京大学 / 蚂蚁 / 上海 AI Lab)是 2025 年——大概也是唯一——真正可在手机上运行的视频-CLIP,而且它直接以 Apple MobileCLIP 为骨干,与本仓库天然衔接。

How

时间维结构重参数化

训练时建立时序结构,推理时折叠掉 —— 沿用 MobileCLIP 的 RepMixer 思路,几乎零额外推理开销,在 InternVid-10M-FLT 上训练。

Base

骨干 = MobileCLIP

Tiny 基于 MobileCLIP-S0,Small 基于 MobileCLIP-S2。这正是本仓库可复用为"视频化"起点的原因。

Specs

端侧规格

Tiny 53.9M / ~12.4 ms;Small 99.4M / ~37.8 ms(iPad Air 2020)。Small K400 零样本 63.1,Tiny 56.2。

对本仓库的启示:MobileViCLIP 提供了把 MobileCLIP-S0/S2 低成本"视频化"用于端侧视频检索的现成范式 —— 若要在此仓库基础上做视频,这是最直接的路径参考。下面据本仓库源码把两处关键实现拆开看。

深挖 A · 源码级时间维结构重参数化(本仓库实现)

本仓库 models/mobileviclip_small.py 揭示了"时间维结构重参数化"的真实做法:把 MobileCLIP 的 RepMixer(空间 2D 令牌混合器)并联一条 1D 时间分支 —— 训练时是多分支,推理时折叠成单个卷积。

  • 双分支 RepMixer(L482–695):训练态同时有空间 mixer/norm(2D MobileOneBlock)与时间 mixer_1d/norm_1d(1D),各带独立 layer_scale / layer_scale_1d;前向先时间混合、再空间混合。
  • 推理折叠(reparameterize(),L624–695):2D 分支折进一个 reparam_conv(Conv2d)、1D 时间分支折进一个 reparam_conv_1d(Conv1d),删除训练态多分支 —— 推理零额外分支,这正是"结构重参数化"省延迟的核心。
  • 注意力阶段的时间嵌入(L1028):最后的 attention stage 加入可学习 temporal_embedding(8 帧),MHSA 在 N=T·H·W 上做联合时空注意力(L397–423)。
  • 冻结骨干、只训时间分支(L54–62):freeze_vision 下,除 mixer_1d / norm_1d / layer_scale_1d 外全部冻结 —— 即"冻结的 MobileCLIP 图像骨干 + 只训练注入的时间分支"。
  • 最终时序平均(FastViT.forward,L1280–1292):T 折进 batch 跑完各 stage,再对 8 帧做均值池化("时序暴力平均")。
# models/mobileviclip_small.py · RepMixer.reparameterize()  (L663–684)
self.reparam_conv    = nn.Conv2d(dim, dim, k, groups=dim, bias=True)   # 空间
self.reparam_conv_1d = nn.Conv1d(dim, dim, k, groups=dim, bias=True)   # 时间
self.reparam_conv.weight.data    = w      # 由 mixer / norm 折叠而来
self.reparam_conv_1d.weight.data = w_1d   # 由 mixer_1d / norm_1d 折叠而来
# 随后 __delattr__ 掉 mixer / norm / mixer_1d / norm_1d —— 推理只剩两个卷积

深挖 B · 源码级图文 → 视频适配 与 InternVid-10M-FLT 数据管线

另一半是"怎么把图像 CLIP 喂成视频 CLIP",以及数据从哪来。

  • 预训练数据 = InternVid-10M-FLT(configs/data.py L6–88):切成 11 个分片(internvid_v1…v11,每片一份 InternVid-10M-flt_N.json 标注 + 视频根目录),合并为 internvid_all;media_type="video"、jump_filter=True(跳过字幕长度过滤)。
  • 图文 → 视频适配(load_checkpoint(),L203–262):从 MobileCLIP 检查点抽取 image_encoder.model.* 权重装入 vision_encoder 并冻结,只训时间分支 —— 把图像 CLIP "升维"成视频 CLIP。
  • 数据集 / 加载:ImgTxtPtTrainDataset(dataset/pt_dataset.py)读 JSON、支持字幕最短长度过滤与多字幕均匀采样;视频用 decord 解码(VIDEO_READER_FUNCS),时间维硬编码 T=8 帧。
  • 损失:标准视频-文本对比 VTC_VTM_Loss.vtc_loss(L89、L124),温度 temp 初值同 ViCLIP(1/100)。
  • 零样本评测语料(configs/data.py L90–143):MSR-VTT-1k / DiDeMo / ActivityNet 检索 + K400 / UCF101 / HMDB51 / SSv2 动作识别(带 kinetics / imagenet prompt 模板)。
与复现计划对齐:这两点正是 notes/replication-plan.md 的 Phase 2 待办("时间维结构重参数化模块"、"图文→视频适配与训练数据管线")。可切入的改进方向:① 更强时序建模(超越 8 帧均值 + 1D 卷积);② 更强文本塔;③ 端侧延迟实测与量化 / token 裁剪。
§ 07

视频 CLIP 全景 · 数据与训练方法

检索天花板仍是 2024 年的 InternVideo2-6B;2025 的动作在数据/训练方法与喂给视频大模型。

视频侧要点

· InternVideo2-6B:MSR-VTT 零样本 55.9 / 微调 62.8,仍是开源天花板。
· VideoPrism-g(Google,检索权重 2025.07 放出)52.7;PE-Core-G 51.2、K400 76.9。
· InternVideo2.5(2025.01)是视频MLLM,用 LRC 把处理帧数扩到 ~10k 帧。
· 两种时序哲学:显式时间注意力 vs PE 的"数据胜过架构"(帧平均池化即可)。

数据 / 训练方法

· 数据筛选:DFN、MetaCLIP(质胜于量)、JEST(算力省 ~10×)、ACID(筛选=蒸馏)。
· 合成字幕:CLIPS 的"反效应"—— 短字幕优于完整长字幕;Recap-DataComp 重写 13 亿图。
· 训练目标:sigmoid 损失(省显存)、纯生成式(OpenVision 2)、掩码(FLIP)、NeuCLIP(小 batch 归一化)。
