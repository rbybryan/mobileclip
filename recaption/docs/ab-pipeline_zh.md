## 0. 一句话总览

同一段视频**独立看 N 遍**、各写一版描述（A 臂整段稠密写 5 遍；B 臂按固定五栏各写 3 遍），
再让**同一个 LLM 只读文字**把 N 版融合成「长稿（不限字数，保细节）+ 短稿（≤30 字训练字幕）」。
**训练用的就是直融短稿那一条。**

**2026-08-05 起默认只跑这两步**（维护者指令：仅优化 A/B 方案真正用到的步骤，其余做成
可选项并默认关闭）。派生、SigLIP 打分、A′ 句切、投票浓缩对照版、GDINO+OCR 画面验真
全部保留在脚本里，但各由一个 `DO_*` 开关控制，默认关；`PIPE_FULL=1` 一键恢复全链。

```
默认开（两步 + 免费哨兵 + 产物）
① 独立重述×N ──A: dense×5──┐   温度0.9 + 帧抖动 + 内容感知选帧(8卡分片)
                            ├─→ ④ 多样性诊断(CPU, 坍缩哨兵, 不可省)
              └─B: slot×3──┘
④b2 直融: 调用1 长稿(不限字数) → 调用2 短稿(≤30字训练字幕)   (8卡分片)
⑥⑦ 全景TSV + 离线评审包(index.html)

默认关（各一个开关，按需打开）
② 派生 DO_DERIVE ─ ③ SigLIP打分 DO_SIGLIP ─ ④ A′切句 DO_APRIME
④b1+④b3 投票浓缩对照版 DO_VOTE
⑤ 短稿验真(GDINO+OCR) → 有✗ → refine最小修改 → 复验 → *_final   DO_VERIFY
```

⑤ 关掉意味着短稿是**未经画面查证**的 LLM 直融稿——做 A/B 方案对比够用，真要把某一批
落成训练数据前，请 `DO_VERIFY=1` 再跑一遍（它是全链唯一的外部幻觉门，计划 §3.5）。

## 1. A/B 两臂对照表

| | **方案 A（dense，主线/默认）** | **方案 B（slot 固定槽位，对比臂）** |
|---|---|---|
| 每遍产出 | 一整段信息密集的稠密描述 | 五个固定栏目的行式短句：人物≤2 / 物体≤2 / 动作≤2 / 场景 1 / 文字 1，空栏必须写「无」 |
| 独立遍数 N | 5 | 3 |
| 派生步 ② | 需要（把每段拆成 2-3 条短句 + gloss） | 不需要（短句 + gloss 随 ① 内联产出） |
| 输出格式 | 自由段落 | 「栏目名：描述 [gloss]」逐行，正则可解析，免 JSON |
| 产物前缀 | `pipe_*` | `pipe_sl_*` |
| 出处 | 计划 §5.5–§5.7 | 计划 §5.6b（ASID 式属性槽位，arXiv 2602.13013） |

曾经还有第三种风格 `struct`（OwlCap 式 JSON caption-set，旧 B 臂），已于 2026-08-05
随代码精简下线——`pipeline-compare` 早已默认对比 dense vs slot，struct 零使用。

**为什么要独立 N 遍**：每遍都可能幻觉，但独立采样下"多遍都说了"的细节大概率是真的。
融合步的一切取舍判断都建立在这个前提上，所以 N 遍之间只靠温度 0.9 + 抽帧抖动制造差异，
绝不给每遍不同的引导——多样性诊断（坍缩哨兵）因此永不跳过。

## 2. 分步说明（两臂共用骨架）

「默认」列 = `pipeline-sample` / `pipeline-compare` 不加任何环境变量时的行为。

| 步 | 默认 | 做什么 | 模型 / 实现 | 输入 → 输出 |
|---|---|---|---|---|
| ⓪ | 开 | 从 RECAPTION 桶队列取 N_SAMPLE 片 | `sed` | `recaption_tasks.jsonl` → `pipeline_sample.jsonl` |
| ① | **开** | 独立重述 ×N（8 卡分片、按 video 续跑） | Qwen3-VL-8B，temp 0.9 / top_p 0.9，看 8 帧，每遍帧位抖动 + 段内内容感知选帧（§2.1） | 视频 → `recap5.*.jsonl`（B：`recap_slot.*.jsonl`） |
| ② | 关 `DO_DERIVE=1` | 仅 A 臂：每段稠密描述 → 2-3 条检索短句 + 英文 gloss（闭集：不重看视频） | Qwen3-VL-8B，temp 0 贪心，纯文本 | `pipe_recaps.jsonl` → `pipe_views.*.jsonl` |
| ③ | 关 `DO_SIGLIP=1` | 逐重述 SigLIP 打分（诊断徽章用） | SigLIP2 so400m-patch16-384 | 重述文本+4 帧 → `*_scores.*.jsonl` |

| ④b1+3 | 关 `DO_VOTE=1` | 投票浓缩对照版（规则计票 → LLM 打包） | CPU 规则 + Qwen3-VL-8B 纯文本 | → `*_units.jsonl` + `*_fused_v.*.jsonl` |
| ⑤ | 关 `DO_VERIFY=1` | 短稿画面验真；有 ✗ 则 refine 最小修改后复验；终稿落 `*_final.jsonl` | GroundingDINO-base fp32 + RapidOCR；修复用 Qwen3-VL-8B | → `*_fused_d_final.jsonl` 等 |
| ⑥⑦ | 开 `DO_TSV=0`/`DO_BUNDLE=0` 可关 | 全景 TSV + 离线评审包（index.html + videos/，可填单选导出） | CPU | → `recap_pipeline*.tsv`、`bundle_*/` |

关掉的步骤在全景 TSV 里出空列，评审页照常出；验真关掉时短稿以 `unverified` 状态进表。
`DO_VOTE=1` 且是 A(dense) 臂时脚本会自动把 `DO_DERIVE` 一并打开——投票需要派生出的 views。

### 2.1 ① 的选帧：8 帧怎么挑（2026-08-05 新增）

维护者的原问题是「为了保证 N 遍互相独立，抽的 8 帧位置错开——可优化：如何挑选这 8 帧？」。
现在分两层，代码在 [`recaption/scripts/frame_pick.py`](../scripts/frame_pick.py)：

1. **哪些帧可选**（`candidate_indices`）：仍是 TSN 均匀分段 + 每遍相位抖动，**一个字没改**。
   这层是 N 遍独立性的来源，动了跨遍一致性就不再是证据。
2. **段内挑哪一帧**（`select_frames`）：每段先给 `FRAME_CAND=3` 个候选（抖动中心 ±0.12 段宽），
   打分挑一帧，评分 = 清晰度（32×32 灰度平均梯度，模糊/叠化得分低）+ 0.5×与上一保留帧的
   画面差异（静止镜头去重），对比度 < 8 的纯黑/纯色转场帧直接一票否决。

为什么值得做：8 帧就是模型看到的**全部证据**，纯均匀抽样会把名额花在运动模糊、转场黑帧、
和与前一帧几乎一样的静止画面上——每浪费一格，可用证据少一格，模型就更容易去补脑。
代价是每遍多解码 16 帧（~0.1s，对比一次生成 ~2s），GPU 侧零开销。

开关：`FRAME_SELECT=content`（默认）/ `uniform`（旧行为，`FRAME_CAND=1` 时逐帧等价，
单测钉死）；`FRAME_CAND` / `FRAME_WINDOW` 可调。窗口别超过抖动步长的一半（0.5/N），
否则各遍会挑到同一批帧——看 `*_diag.txt` 的 COLLAPSE 旗。

## 3. ④b 融合（核心步骤）

**版本一「直融」= 终稿、默认唯一开着的融合**（计划 §5.7 v5，两次纯文本调用、贪心解码）。
2026-08-05 起它和 ① 一样按 `FUSE_GPUS`（默认 = `NGPU` = 8）**多卡数据并行分片**：纯文本
步骤，显存/吞吐特性与重述一致，直接线性加速（A 臂实测 31.8 s/片 → 理论 ~4 s/片）。
卡被别人占时 `FUSE_GPUS=1` 退回单卡前台。改卡数后建议先 `rm ${P}_fused_d.*.jsonl`，
否则旧分片文件里的片会被新分片重算一遍（续跑是按分片自己的输出去重的）。

1. **调用 1（长稿）**：读 N 段独立重述，像字幕编辑一样做判断式取舍——多段一致→保留；
   矛盾→取多数或模糊化；单源细节按类型分治（动作/位置这类难编造的可留，数字/画面文字/
   人名/情绪这类易幻觉的舍弃或模糊化）——输出**不限字数的长稿**（保留全部过审细节）
   和**带理由的 dropped 清单**（审计用）。
2. **调用 2（短稿）**：只读长稿（闭集，判断已经做完），提炼**一条 ≤30 字的自然句**
   ——这就是训练字幕（CLIP 文本编码器 32-token 窗：[CLS]+~30 汉字+[SEP]）。

**版本二「投票浓缩」= 对照诊断，默认关**（计划 §5.5，`DO_VOTE=1` 打开）：`fuse_condense.py` 用 CPU 规则跨遍聚类
计票（3-gram Jaccard≥0.35 或共享 gloss 名词），支持数 ≥2 的单元过票，LLM 只负责把过票
单元打包成 2-5 条 ≤28 字短句。它的价值是给直融当参照：直融短稿里出现了投票落选的细节、
或漏了高票单元（MISS 哨兵），都是要人工看一眼的信号。

## 5. Prompt 全文

以下即模型实际收到的文字（源码在 `recaption/scripts/vlm_audit.py`；源码里经 `.format`
消费的几条把 `{}` 写成 `{{}}`，此处按渲染后展示；`{n}`/`{recaps}`/`{long}`/`{dense}`/
`{units}`/`{items}` 是运行时填充的占位符）。

### 5.1 A 臂重述 `RECAP_PROMPT`（①，随帧输入，temp 0.9）

```text
你是一个严谨的视频画面描述助手。下面是从同一段视频中按时间先后均匀抽取的若干帧画面。
请把这些画面综合成一段用于训练的中文描述，尽可能覆盖所有真实可见的信息，同时绝不编造。

严格遵守以下规则：
1. 只描述画面中清晰可见的内容。看不清、不确定、被遮挡或需要推测的内容一律省略，不要猜测。
2. 不要描述画面之外的信息：不要推断拍摄地点、时间、人物身份、情绪动机、事件的前因后果，也不要脑补画面外正在发生的事。
3. 按动作在画面中出现的先后顺序来叙述，用“先”“接着”“随后”“最后”等词表示顺序。禁止出现帧号、秒数、时间戳或“第几张图/第几帧/视频/画面/图片”这类元描述词。
4. 屏幕上的文字（字幕、标题、标牌、水印等）：只有当文字清晰可辨时，才用中文引号“”原样照抄；不要翻译、不要补全、不要猜测残缺的文字；无法辨认时直接不提这段文字。
5. 数量：只有在数量很少且能明确数清时才给出具体数字；否则用“几”“一些”“一群”“许多”等模糊量词，绝不编造精确数目。
6. 覆盖以下方面（只写真实可见的）：主体（人/物的外观、服装、颜色等特征）、主体的动作及其先后、场景与背景环境、屏幕上的文字。如果某一方面在画面中不存在，就完全不要提它。
7. 输出一段连贯、信息密集的中文，不要分点、不要标题、不要开场白或结束语，只输出这段描述本身。
```

### 5.2 B 臂重述 `SLOT_RECAP_PROMPT`（①，随帧输入，temp 0.9）

```text
你是一个严谨的视频画面描述助手。下面是从同一段视频中按时间先后均匀抽取的若干帧画面。
请按下面五个固定栏目描述画面，每行一条，格式为「栏目名：描述 [gloss]」。

栏目与行数：
人物：视频里的人或动物等活动主体及其外观特征（最多 2 行；没有就写「无」）
物体：画面中对内容有意义的主要物品及其特征（最多 2 行；只写主要的，没有就写「无」）
动作：人物或物体的动作及其先后（最多 2 行；先后用"先""随后""最后"表达）
场景：场景与背景环境（1 行）
文字：画面上清晰可辨的文字，用中文引号“”原样照抄（1 行）

严格遵守：
1. 每行描述不超过 28 个字，语法完整、可独立成句，不用"他/她/它/这"开头。
2. 只写画面中清晰可见的内容；看不清、被遮挡、需要推测的一律省略。某栏目在画面中不存在时，该行写「无」——绝不为了填满栏目而编造。
3. 不写画面之外的信息：不推断地点名称、拍摄时间、人物身份、情绪动机、前因后果；禁止出现帧号、秒数、时间戳或"第几张图/第几帧/视频/画面"这类词。
4. 文字栏只在清晰可辨时原样照抄，不翻译、不补全、不猜测残缺文字；辨认不出就写「无」。
5. 数量只有很少且能数清时才给具体数字，否则用"几""一些""一群"等模糊量词。
6. 行尾方括号内给该行能在画面中被检测到的具体名词的英文（小写，逗号分隔，0-4 个）；没有可检测名词写 []；「无」行不加方括号。
7. 只输出这些行，不要任何解释、编号、标题或空行。

输出示例：
人物：一名穿红色围裙的中年男子 [man,apron]
物体：案板上放着一把菜刀 [knife]
动作：男子先把黄瓜切成薄片，随后装进盘中 [cucumber,plate]
场景：明亮的家用厨房操作台 [kitchen]
文字：无
```

### 5.3 A 臂派生 `DERIVE_PROMPT`（②，纯文本，temp 0）

```text
你会看到一段视频的中文稠密描述。请把它改写成 2-3 条互补的中文检索短句，并给每条短句配英文检测标签。

规则：
1. 每条短句不超过 28 个字，语法完整、可独立成句，不用"他/她/它/这"开头。
2. 2-3 条合起来覆盖原描述的主要信息，彼此侧重不同（如：主体+动作 / 场景环境 / 画面文字），不要互相复述。
3. 只能使用原描述里已有的信息，不得新增任何细节；原描述里用引号“”照抄的画面文字，短句中原样保留。
4. gloss：该短句里能在画面中被检测到的具体名词的英文（小写，1-4 个），如 ["man", "kitchen", "knife"]；抽象概念、动词、顺序词不要放。
5. 只输出一个 JSON 对象，不要任何解释或多余文字，格式：
{"views": [{"text": "短句一", "gloss": ["...", "..."]}, {"text": "短句二", "gloss": ["..."]}]}

原描述：
{dense}
```

### 5.4 直融·调用 1 长稿 `FUSE_LONG_PROMPT`（④b，纯文本，贪心）

```text
下面是同一段视频的 {n} 段互相独立的中文描述。它们出自对同一段视频的多次独立观看，各自都可能有错漏；多段一致的信息通常更可信，但一致与否只是证据、不是铁律——请你像资深字幕编辑一样综合判断。

请在心里分三步完成编辑，最后只输出结果 JSON：

第一步·抓重点：先确定这段视频的核心内容——主要的人/物是谁、正在发生什么。

第二步·辨真伪，对每个细节做取舍：
- 多段独立提到且不矛盾 → 可信，保留；
- 各段互相矛盾（颜色、数量、动作不一致）→ 取多数说法；没有多数就舍弃，或改用更模糊但稳妥的说法（如把存疑的"两名男子"写成"男子"）；
- 只有一段提到 → 看类型：具体的动作、位置这类"难凭空编造"的细节可酌情保留；数字、画面文字内容、品牌/人名、身份、情绪意图这类"易幻觉"的细节一律舍弃或模糊化；
- 引号“”内的画面文字：多段一致才保留且必须原样照抄、不改一字；只有一段提到或各段不一致，就完全不写这段文字。

第三步·成长稿：把**全部**通过取舍的信息写成一段连贯自然的中文描述，按"主体→动作先后→场景→画面文字"组织。**长度不设限制**——以完整覆盖保留信息为准，宁全勿缺；但只写你判定保留的信息，绝不新增任何描述之外的内容，也不要逐帧流水账式复述。

另外输出 dropped：被你舍弃或模糊化的细节清单，每条在括号里附一句取舍理由，如 "墙上挂着三幅画（仅一段提及，数字类易幻觉）"。

只输出一个 JSON 对象，不要任何解释：
{"long": "一段完整的长描述（不限字数）", "dropped": ["细节（取舍理由）", "..."]}
```

## 6. 怎么跑 + 分段计时怎么读

```bash
# 单臂（默认 A；B 臂加 RECAP_STYLE=slot）—— 默认= ①重述 + ④b2直融，两步都 8 卡分片
N_SAMPLE=50 bash recaption/scripts/run_v100.sh pipeline-sample

# 测真实全量成本：取冷样本（前 50 片有缓存会虚低）
SAMPLE_OFFSET=200 N_SAMPLE=50 bash recaption/scripts/run_v100.sh pipeline-sample

# 要落训练数据前，把画面验真加回来（唯一外部幻觉门）
DO_VERIFY=1 N_SAMPLE=50 bash recaption/scripts/run_v100.sh pipeline-sample

# 老的全链（含派生/打分/A′/投票/验真）一键恢复
PIPE_FULL=1 N_SAMPLE=50 bash recaption/scripts/run_v100.sh pipeline-sample

# 选帧消融：内容感知(默认) vs 旧的纯均匀+抖动
FRAME_SELECT=uniform N_SAMPLE=50 bash recaption/scripts/run_v100.sh pipeline-sample
```

**开关全表**（都是环境变量，默认值即下表的「默认」列）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `DO_DERIVE` | 0 | ② A 臂派生（58 s/片；`DO_VOTE=1` 时 dense 臂自动带上） |
| `DO_SIGLIP` | 0 | ③ SigLIP 逐重述打分 |
| `DO_APRIME` | 0 | ④ A′ 句切 |
| `DO_VOTE` | 0 | ④b1 计票 + ④b3 投票打包（对照诊断版） |
| `DO_VERIFY` | 0 | ⑤ GDINO+OCR 验真 + ✗ refine 复验 |
| `DO_DIAG` | 1 | ④ 多样性/坍缩诊断（CPU 免费，独立采样的唯一哨兵，别关） |
| `DO_TSV` / `DO_BUNDLE` | 1 | ⑥ 全景 TSV / ⑦ 离线评审包 |
| `PIPE_FULL` | 0 | 1 = 上面全开（老行为）；`PIPE_LEAN=1` 仍可在全开基础上压掉 ③④A′ |
| `FUSE_GPUS` | `NGPU`(8) | ④b2 直融分片卡数；1 = 单卡前台 |
| `FRAME_SELECT` | `content` | `uniform` = 旧的纯均匀+抖动；`FRAME_CAND`(3)/`FRAME_WINDOW`(0.12) 微调 |

**改了开关/选帧后要重算的话，先删对应产物**——所有 LLM 步骤都按 video 续跑，旧结果不会
自动重来：重述 `rm $OUT/recap5.*.jsonl`（B 臂 `recap_slot.*`）、直融 `rm $OUT/pipe*_fused_d.*.jsonl`。
